# 文档索引与使用规则

> 更新日期：2026-07-31
>
> 本目录同时保存当前规范、报告素材和历史资料。开发和答辩时必须先确认文档类别，不能把历史方案中的目标指标当成当前实现结果。

## 当前有效依据

按优先级使用：

1. `contracts/*.json` 与当前代码：机器可执行契约和实际行为的最高依据。
2. `README.md`、`CHANGELOG.md`：当前版本、启动方式、测试结果和已知限制。
3. `docs/00-事件字典.md`：13 类事件、优先级和状态机的人读规范。
4. `docs/01-MQTT契约.md`、`docs/06-接口规范.md`：MQTT、REST 和云边推理接口；两者修改必须保持一致。
5. `docs/07-测试用例.md`、`docs/08-部署指南.md`、`docs/12-上传规范.md`：测试、部署和协作执行规范。
6. `项目任务书-2026执行版.docx`：2026 年 8 月执行分工、里程碑、验收指标和当前进度。

## 历史资料

`docs/archive/` 保存旧骨架交付说明、旧团队分工和 React 前端交接文档。这些文件保留用于追溯，不作为当前任务分工或前端技术路线依据。当前前端实现是 Vue 3 + Vite + Element Plus。

`对话梳理-项目规划总结.md` 是过程上下文文件，仍可帮助新成员了解决策背景，但其中的待办和指标可能滞后，不属于正式接口规范。

## 更新规则

- 事件字段先改 `contracts/`，再同步 `00`、`01`、`06` 和报告章节。
- 测试数量、性能数据和完成状态只从可复现命令或原始日志更新，不凭估计填写。
- 新增文档必须注明“当前实现”还是“目标方案”，并写明日期和代码版本。
- 旧文档优先移动到 `archive/`，不直接删除，避免丢失方案演进依据。
