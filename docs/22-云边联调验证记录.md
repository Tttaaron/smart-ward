# 云边协同推理联调验证记录

> 联调方法 + 2026-08-10 实测结果（亚伦，本地 amqtt broker + 本地双服务）
> 配套脚本：`scripts/mqtt_cloud_sync_test.py`

## 一、联调链路

```
edge-agent                        Broker                        cloud-llm-service
  ├─ 事件融合 → task_router 决策卸载                                 │
  ├─ publish_inference_request ──► ward/W-01/node/{node}/           │ 订阅:
  │                                  inference/request  (QoS1)      │   ward/+/node/+/inference/request
  │◄── node/{node}/inference/response ◄─────────────────────────────┤  去重/幂等 → LLMClient 研判 → 回传
  └─ resolve(event_id,trace_id) → SQLite 写回 details.cloud_inference
```

- 主题：请求 `ward/{ward_id}/node/{node_id}/inference/request`；响应 `node/{node_id}/inference/response`
- 关联：`event_id + trace_id`；超时：边缘 `ROUTER_CLOUD_TIMEOUT_S`（默认 5s）
- 云端可用性统计：`GET /stats`（total_requests / total_responses / total_errors / pending_dedup）

## 二、联调环境（两种）

### 方式 A：Docker 全容器（推荐，贴近真实）

```powershell
docker compose up -d mqtt-broker cloud-llm-service edge-bed-01
# 验证云端已订阅
docker compose logs -f cloud-llm-service
curl http://localhost:8005/health
```

> 注：不要 `up` 全部服务——diffusion-service 声明了 NVIDIA GPU 资源，
> 无 GPU 机器会启动失败（见 docs/19 §A1）。

### 方式 B：本地轻量（无 Docker / Docker 未启动时）

```powershell
# 1) 依赖
pip install paho-mqtt==1.6.1 amqtt -i https://pypi.org/simple

# 2) 本地 broker（amqtt 纯 Python，1883，QoS 0/1）
python - <<'EOF'
import asyncio
from amqtt.broker import Broker
async def main():
    b = Broker()
    await b.start()
    await asyncio.sleep(3600)
asyncio.run(main())
EOF

# 3) cloud-llm-service（另开终端）
cd cloud-llm-service
MQTT_BROKER=localhost MQTT_PORT=1883 LLM_MODE=mock python -m uvicorn app.main:app --port 8004

# 4) edge-bed-01（另开终端；阈值调高让事件走云端路径）
cd edge-agent/src
WARD_ID=W-01 BED_ID=B01 EDGE_NODE_ID=EDGE-W01-B01 MQTT_BROKER=localhost \
MQTT_PORT=1883 CAMERA_MODE=mock LLM_MODE=mock TICK_SECONDS=3 \
ROUTER_EDGE_THRESHOLD=0.95 SCENARIO_PROFILE=fall_suspected,nurse_call python main.py
```

> Windows 环境变量写法用 `$env:KEY="value"` 多行 PowerShell；Git Bash 用上述 `KEY=val` 前缀。

## 三、7 场景联调（验收口径：每场景 ≥20 次）

| # | 场景 | 操作 | 通过判据 |
|---|---|---|---|
| 1 | 正常 | `python scripts/mqtt_cloud_sync_test.py --scenario normal --count 20` | 响应数=请求数，judgment 合法，trace 关联 |
| 2 | 重复 | `--scenario duplicate --count 20` | 20 次相同 event_id 仅 1 次响应（云端去重） |
| 3 | 超时 | 停 cloud-llm-service 后 `--scenario timeout --count 20` | 0 响应；边缘 DB 写 `fallback_edge/timeout` |
| 4 | 非法 | 边缘侧验证：云端返回非法 judgment 时写 `fallback_edge/invalid_judgment`（mock 不会产生，可临时改 LLMClient 或抓包改响应） | 边缘不崩溃、本地决策生效 |
| 5 | 未知 | 手动发指向不存在 event_id 的响应 | 边缘忽略，无副作用 |
| 6 | trace | 响应 trace_id 与请求不一致 | 边缘丢弃不匹配响应 |
| 7 | 断网 | `docker network disconnect` 边缘容器 → 恢复 | 断网期间本地自治；恢复后补传、云端重新响应 |

## 四、2026-08-10 实测结果（方式 B）

| 验证项 | 结果 | 证据 |
|---|---|---|
| 正常闭环 | ✅ 2/2 request→response，judgment=escalate（conf 0.5 mock 规则） | 脚本输出 + `/stats` |
| 边缘自动卸载 | ✅ 边缘场景事件自动上送云端，`/stats` 累计 6 请求 6 响应 0 错误 | `/stats` |
| 边缘写回 | ✅ SQLite `details.cloud_inference.status=completed`，judgment=confirm（P1+conf≥0.7），trace 关联 | `edge-agent/src/data/edge_EDGE-W01-B01.db` |
| 重复去重 | ✅ 同一 event_id ×3 仅计 1 次 | `/stats` 计数变化 |
| 超时回退 | ✅ 停云端后新事件 `status=fallback_edge, reason=timeout` | SQLite |

**结论**：云端 mock 链路与边缘写回闭环已实测打通，可进入与 P5 的真实 Broker 联调取证阶段。
