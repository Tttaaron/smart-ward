# 27. 日常活动识别评测方案

> 状态：工具就绪，**待采集数据**。7 类日常活动（walking/eating/playing_phone/sleeping/sitting/standing/lying）此前没有任何量化评测数据，`docs/02-边缘模型选型对比.md` 中"误报率≤10%、姿态分类≥85%"等指标一直标 ⏳ 待实测。本文档定义采集规范与评测方法，配套脚本 `edge-agent/scripts/eval_activity.py`。

## 一、评测链路（与生产完全一致）

脚本逐帧复现 `adapters/yolo_camera.YoloCameraAdapter.read()` 的处理顺序：

```
YOLO-Pose 推理 → parse_yolo_result → IoUTracker（轨迹 ID）
→ BehaviorAnalyzer（姿态平滑 + fall/tremor 特征）
→ ActivityRecognizer（规则分类 + 5 帧滞回确认）
→ build_activity_entry（主活动标签）
```

片段级预测 = 片段内所有非 unknown 帧标签的多数投票。

时间戳按 `帧号 / fps` 折算为真实秒数，保证时长型规则（sleeping ≥60s、standing/sitting 持续 ≥5s）与真实时间同尺度，`--stride > 1` 加速时依然成立。

## 二、片段采集规范

### 命名约定

```
{label}__{subject}__{take}.mp4
例：sitting__subjectA__01.mp4、lying__subjectB__03.avi
```

label 仅限 7 类之一；双下划线分隔；不合规命名的文件会被跳过并告警。

### 数量与时长

| 项目 | 要求 | 说明 |
|---|---|---|
| 每类片段数 | ≥20 段（最低 10 段出初步数字） | 支撑 P/R 的统计意义 |
| 单段时长 | 15~30 秒 | **sleeping 例外：≥75 秒**（规则要求躺姿持续 ≥60s，留余量） |
| 有效帧下限 | 每段 ≥10 帧（默认，可调） | 低于则报告中告警 |

### 场景多样性清单

- [ ] ≥2 名被摄者、不同衣着（宽松/紧身、深浅色）
- [ ] 正常光照 + 弱光各一批（对应 quality.degraded 降级路径）
- [ ] 部分遮挡场景（被子盖腿的 lying、桌沿挡下半身的 sitting）
- [ ] 相机角度变化（正对/侧向/俯角）
- [ ] 干扰段：护工/家属进入画面（**同时验证 MULTI_PERSON_GUARD 多人防护**，见 `docs/22` §8 与 fusion.py）

## 三、运行方法

```powershell
# 依赖：pip install -r edge-agent/requirements-yolo.txt
python edge-agent/scripts/eval_activity.py `
    --clips-dir data/activity_eval `
    --model yolo11n-pose.pt `
    --out docs/evidence/activity-eval-首次评测.json
```

输出：逐片段 ✅/❌ 明细、总体 accuracy、每类 Precision/Recall/F1/support、混淆矩阵；JSON 报告含元信息（模型/conf/stride/耗时），存入 `docs/evidence/` 作为证据。

## 四、已知边界（如实记录，评测前必读）

1. **sitting 类当前在真实管线不可达**。粗姿态估计（`behavior.estimate_posture`）只会输出 standing/lying/unknown 三态，而 ActivityRecognizer 的 sitting 分支要求 posture=="sitting"——该标签只有 mock 场景注入才出现。评测时 sitting 片段预计大量落入 unknown/standing：这是模型能力缺口，不是脚本缺陷。补法：在 `_classify` 里加"髋部屈曲约 90°"的关键点几何分支。
2. **standing/lying 可达**（来自关键点离散度/bbox 宽高比），standing 还需持续 ≥5s；短站起坐动作可能被滞回吞掉，属设计行为（防抖优先）。
3. sleeping 是 lying 的超集（≥60s），短躺片段会归为 lying——混淆矩阵里两者互相渗透是预期现象，解读时看合并口径。
4. walking/eating/playing_phone 为纯关键点几何规则，对关键点置信度敏感；检测质量差的片段会大量输出 unknown。
5. 跌倒相关（fall_score）不在本脚本范围，已有 UR Fall 数据集评测（`docs/21`，帧级准确率 95.78%）。

## 五、判定标准与后续动作

| 指标 | 目标（对齐 docs/02） | 不达标时的动作 |
|---|---|---|
| 每类 F1 | ≥0.80 | 优先调该类几何阈值（activity_tracker.py 常量区），重跑对比 |
| overall accuracy | ≥0.85 | 分析混淆矩阵找主要混淆对 |
| unknown 占比 | ≤15% | 检查关键点置信门槛与拍摄质量 |

数据齐并出首轮报告后，再启动跌倒召回优化实验（参考 `test/yolo-fall-detection` 分支的关键点置信度 0.15 方案），用同一套片段做回归对比。
