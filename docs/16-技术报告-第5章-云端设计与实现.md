## 5.2 数据库设计

### 5.2.1 11 张表 ER 关系

```
wards (病区)
  ├── beds (床位)            FK ward_id -> wards
  ├── edge_nodes (边缘节点)   FK ward_id -> wards
  └── shift_summaries (交接班) FK ward_id -> wards

observations (观测数据)       ward_id + node_id + bed_id

safety_events (安全事件)      ward_id + node_id + bed_id
  ├── alert_tasks (告警任务)  FK event_id -> safety_events
  └── event_dispositions (处置记录) FK event_id -> safety_events

model_versions (模型版本)
model_deployments (模型部署)   node_id

audit_logs (审计日志)          target_type + target_id
```

### 5.2.2 核心表结构

**safety_events（安全事件，核心表）**：

| 字段 | 类型 | 说明 |

| state | VARCHAR(20) | 6 态状态机 |

| model_name / model_version | VARCHAR | 模型信息 |
| inference_ms | INT | 推理耗时 |
| evidence_refs / rule_hits / details | JSON | 事件扩展字段 |
| occurred_at / detected_at / acknowledged_at / resolved_at | DATETIME | 时间线 |

**索引设计**：
- `idx_ward_state`：按病区+状态查询（护士站待处理列表）
- `idx_bed_time`：按床位+时间查询（床位历史）
- `idx_priority_state`：按优先级+状态查询（P1 待处理统计）

## 5.4 MQTT 处理器设计

### 5.4.1 订阅清单与消息分发

```python
topics = [
    ("ward/+/node/+/observation", 1),  # -> _handle_observation
    ("ward/+/node/+/event", 1),        # -> _handle_event
    ("ward/+/node/+/health", 1),      # -> _handle_health
    ("ward/+/alert/+/ack", 1),        # -> _handle_ack
]
```

`_on_message` 按 topic 段数和关键字分发到 4 个处理器。

### 5.4.2 四个处理器职责

| 处理器 | 触发主题 | 职责 |
|---|---|---|
| `_handle_observation` | observation | 逐源写 observations 表 + WS 广播 |
| `_handle_event` | event | 幂等写 safety_events + 创建 alert_task + 审计 + WS 广播 |
| `_handle_health` | health | 更新/注册 edge_nodes + WS 广播节点状态 |
| `_handle_ack` | ack | 更新事件状态机 + 写处置记录 + 审计 + WS 广播 |

### 5.4.3 event_id 幂等去重

```python
def _handle_event(self, data):
    event_id = data.get("event_id")
    existing = db.query(SafetyEvent).filter_by(event_id=event_id).first()
    if existing:
        logger.debug(f"事件已存在，跳过: {event_id}")
        return  # 幂等丢弃重复
    # 写入新事件 + 创建告警任务 + 审计
```

断网补传产生的重复消息按 `event_id` 唯一约束自动丢弃。

### 5.4.4 重连机制

使用 paho 原生 `reconnect_delay_set(min=2, max=60)` 指数退避，`_on_disconnect` 仅记录日志不阻塞网络循环线程。

## 5.5 WebSocket 推送设计

### 5.5.1 推送机制

MQTT 处理器收到消息后，通过 `broadcast_sync()` 桥接到 WebSocket 推送给所有前端连接：

```python
# mqtt_handler（paho 回调线程）
if self.ws_manager:
    self.ws_manager.broadcast_sync({
        "type": "safety_event",
        "event_id": event_id,
        "priority": priority,
        ...
    })

# websocket_manager（asyncio 主线程）
def broadcast_sync(self, message):
    asyncio.run_coroutine_threadsafe(self.broadcast(message), self.loop)
```

### 5.5.2 心跳检测

WebSocket 连接 30 秒心跳：
- 每 30 秒发送 `{"type": "ping"}`
- 前端回 `{"type": "pong"}`
- 超过 40 秒未响应则断开

### 5.5.3 推送消息类型

| type | 触发 | 前端处理 |
|---|---|---|
| `safety_event` | 边缘上报新事件 | 告警工作台 unshift |
| `event_ack` | 护士确认事件 | 更新事件状态 |
| `observation` | 边缘上报观测 | 床位状态更新 |
| `node_health` | 节点心跳 | 节点状态刷新 |
| `shift_summary` | 生成交接班摘要 | 刷新摘要列表 |

### 5.6.3 事件处置交互

告警工作台每个事件卡片有 4 个按钮，对应事件状态机的 4 个 action：

```javascript
const onAck = async (evt, action) => {
  await api.ackEvent(evt.event_id, {
    action,  // acknowledge / resolve / false_positive / escalate
    operator_id: 'nurse-demo',
    operator_name: '演示护士',
    operator_role: 'nurse',
  })
  // 乐观更新本地状态
  const stateMap = {
    acknowledge: 'acknowledged',
    resolve: 'resolved',
    false_positive: 'false_positive',
    escalate: 'escalated',
  }
  evt.state = stateMap[action]
}
```

点击按钮立即更新本地状态（乐观更新），同时 POST 到云端，云端通过 MQTT 下发到边缘端 + WS 广播给其他客户端。
