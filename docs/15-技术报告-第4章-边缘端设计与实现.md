## 4.1 边缘代理总体设计

### 4.1.1 设计目标

边缘代理部署在每个床位的 Orange Pi 5（RK3588 6TOPS NPU）上，需实现：

| 目标 | 要求 | 实现方式 |
|---|---|---|
| 实时识别 | 跌倒/坠床/抽搐秒级检测 | YOLOv8n-pose INT8 + NPU 加速 |
| 多源融合 | 摄像头+床垫+输液+环境四源 | 融合引擎 12 条规则 |
| 断网自治 | 断网时本地告警不中断 | SQLite 缓存 + synced 补传 |
| 模型可演进 | 灰度下发新版本 | load_model/rollback + health 上报 |
| 隐私合规 | 原始视频不出本地 | 仅上传脱敏 evidence_refs 指针 |

### 4.1.3 数据流

每个采集周期（默认 3 秒，`TICK_SECONDS`）执行一次：

```
1. scenario.tick()              推进场景状态机
2. 采集适配器.read()             4 类传感器读取 -> Observation[]
3. inference.run(camera_obs)    摄像头推理 -> InferenceResult
4. fusion.fuse(obs, inf)        多源融合 -> SafetyEvent[]
5. _publish_events()            保存 SQLite + MQTT 上报
6. 每 10 周期 _publish_health()  节点心跳
7. sync_offline_data()          补传断网期间事件
8. 每 100 周期 cleanup_old_data() 清理旧观测
```

## 4.2 采集适配器设计

### 4.2.1 BaseAdapter 抽象基类

所有适配器继承 `BaseAdapter`，统一 `read() -> Observation` 接口，真实硬件接入时只替换 `read()` 实现：

```python
class BaseAdapter(ABC):
    SOURCE_TYPE = "base"

    def __init__(self, node_id: str, bed_id: str):
        self.node_id = node_id
        self.bed_id = bed_id

    @abstractmethod
    def read(self) -> Observation:
        """读取一次观测数据，返回标准化的 Observation"""
        raise NotImplementedError
```

`Observation` 标准结构：

```python
@dataclass
class Observation:
    source_type: str        # camera / bed_sensor / infusion / environment
    data: Dict[str, Any]    # 源特有数据
    quality: Quality        # confidence / latency_ms / degraded
    timestamp: str          # ISO 8601 UTC
```

`quality` 三字段供融合引擎做置信度加权：
- `confidence`（0~1）：模型/传感器置信度
- `latency_ms`：采集耗时
- `degraded`：是否降级（遮挡/低照度/故障）

### 4.2.2 四类采集适配器

| 适配器 | source_type | 数据字段 | 默认采集周期 |
|---|---|---|---|
| CameraAdapter | camera | presence/person_count/posture/bbox/pose_keypoints/fall_score/tremor_score/position_duration/call_requested | 3s |
| BedSensorAdapter | bed_sensor | occupied/bed_state/absence_seconds/pressure_raw | 3s |
| InfusionAdapter | infusion | flow_rate/volume_pct/remaining_minutes/anomaly | 5s |
| EnvironmentAdapter | environment | temperature/humidity/light/co2/door_open/air_quality | 10s |

**CameraAdapter**（当前模拟版，真实接入时替换 read()）：

```python
class CameraAdapter(BaseAdapter):
    SOURCE_TYPE = "camera"

    def read(self) -> Observation:
        # 默认状态：床位有人静坐
        presence, posture, fall_score = True, "sitting", 0.0
        # 场景驱动：scenario 注入状态覆盖默认值
        if self.scenario is not None:
            cam_state = self.scenario.get_camera_state()
            if cam_state:
                posture = cam_state.get("posture", posture)
                fall_score = cam_state.get("fall_score", fall_score)
                # ... 透传 tremor_score/position_duration/call_requested
        # 真实硬件接入时：
        #   ret, frame = cv2.VideoCapture(0).read()
        #   result = inference_engine.run(frame)
        return Observation(source_type=self.SOURCE_TYPE, data={...}, quality=Quality(...))
```

**BedSensorAdapter** 输出占床/离床状态与持续时长，真实接入时替换为 ESP32+FSR402 压力传感器读数。`absence_seconds` 是离床判定的核心字段。

**InfusionAdapter** 输出滴速/液位/异常状态，`anomaly` 字段枚举 normal/fast/slow/low_volume/completed/interrupted，由 `flow_rate` 与 `volume_pct` 自动判定。

**EnvironmentAdapter** 输出温湿度/CO₂/光照/门磁，用正弦波+噪声模拟环境波动，真实接入时替换为 Modbus/BLE/LoRa 网关读数。

## 4.3 融合引擎设计

### 4.3.1 设计原则

融合引擎 `fusion.py` 采用**纯函数式**设计：每周期 `fuse(observations, inference) -> List[SafetyEvent]`，只消费 `InferenceResult + Observation`，不直接调 scenario。模型升级时只替换 `inference.py`，fusion 一行不改。

### 4.3.2 12 条规则

| 规则 | 事件 | 优先级 | 消费字段 | 触发条件 |
|---|---|---|---|---|
| 1 | fall_suspected | P1 | posture, fall_score | posture=falling AND fall_score>0.5 |
| 2 | bed_leave | P2 | absence_seconds, occupied, bbox | 床垫离床 + bbox 床区多边形校验 |
| 3 | infusion_anomaly | P2 | anomaly, flow_rate, volume_pct | anomaly != normal |
| 4 | environment_anomaly | P3 | temperature, co2, light | 超阈值（温度/CO₂/光照） |
| 5 | door_departure | P2 | door_open, presence | 门磁开 + 摄像头有人 |
| 6 | fall_prediction | P1 | posture, fall_score, occupied | lying_edge + fall_score + 占床 |
| 7 | long_still | P2 | posture, position_duration | 同一体位≥5分钟 |
| 8 | abnormal_posture | P2 | posture | curled/leaning/grabbing_chest |
| 9 | seizure | P1 | tremor_score | tremor_score 超阈值 |
| 10 | bedsore_risk | P3 | posture, position_duration | 同一体位≥2小时 |
| 11 | device_fault | P3 | quality.degraded | 传感器降级≥60秒 |
| 12 | nurse_call | P1 | call_requested | 呼叫按钮触发（透传） |

### 4.3.3 去重机制

同类事件去重：`EVENT_DEDUPE_SECONDS`（默认 30 秒）内同类事件不重复触发，避免持续状态产生告警风暴。

```python
def _should_fire(self, event_type: str) -> bool:
    now = datetime.now(timezone.utc)
    last = self._last_fired.get(event_type)
    if last and (now - last).total_seconds() < self.dedupe_seconds:
        return False
    self._last_fired[event_type] = now
    return True
```

### 4.3.4 阈值全可配

8 个阈值通过环境变量配置，支撑病房画像差异化（rehab 离床 20s、pediatric 15s）：

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `BED_LEAVE_THRESHOLD` | 30 | 离床秒数阈值 |
| `BED_EDGE_FALL_SCORE` | 0.6 | 坠床预警 fall_score 阈值 |
| `LONG_STILL_SECONDS` | 300 | 长时间静止秒数 |
| `TREMOR_THRESHOLD` | 0.6 | 抽搐 tremor_score 阈值 |
| `BEDSORE_DURATION` | 7200 | 压疮持续秒数 |
| `DEVICE_FAULT_DEGRADED_SECONDS` | 60 | 设备故障降级秒数 |
| `EVENT_DEDUPE_SECONDS` | 30 | 去重窗口 |
| `BED_REGION_POLYGON` | 空 | 床区多边形（离床双源校验） |

## 4.4 推理引擎设计

### 4.4.1 InferenceEngine 接口

推理引擎强制输出 5 字段（对齐方案书 §3.3 验收与契约）：

```python
class InferenceResult:
    model_name: str          # 模型名（如 yolo-nano-pose / rule-fusion-v1）
    model_version: str       # 语义化版本（如 1.0.0-int8）
    confidence: float        # 置信度 0~1
    inference_ms: int        # 推理耗时毫秒
    evidence_refs: List      # 脱敏证据引用
    predictions: Dict        # posture/fall_score/tremor_score 等 8 字段
```

### 4.4.2 当前实现与目标实现

| 项 | 当前（v0.2.0） | 目标（硬件接入后） |
|---|---|---|
| model_name | rule-fusion-v1 | yolov8n-pose-rknn |
| model_version | 0.1.0-mock | 1.0.0-int8 |
| run() 内部 | time.sleep(5ms) + 透传适配器字段 | rknn.infer(frame) + 关键点几何后处理 |
| predictions | 透传 8 字段 | YOLO 原生 bbox+keypoints -> posture/fall_score/tremor_score |
| evidence_refs | 按风险填充指针 | 真实脱敏截图存储到 /app/evidence/ |

接口签名 `run(camera_obs) -> InferenceResult` 稳定，真实模型接入时只改内部实现，fusion/mqtt/main 一行不动。

### 4.4.3 模型版本管理

支撑云端 `model/deploy` 灰度下发：

```python
def load_model(self, model_name, model_version) -> bool:
    # 记录上一版本以便回退
    self._prev_model_name = self.model_name
    self._prev_model_version = self.model_version
    self.model_name = model_name
    self.model_version = model_version
    return True

def rollback(self) -> bool:
    # 回退到上一稳定版本
    self.model_name = self._prev_model_name
    self.model_version = self._prev_model_version
```

加载失败自动回退并标记 `model_status=degraded`，confidence 降低兜底。

### 4.4.4 evidence_refs 证据收集

按风险等级填充脱敏证据指针，对齐契约 `kind: image/clip/sensor_dump/pose_keypoints`：

```python
def _build_evidence_refs(self, camera_obs, predictions):
    refs = []
    # 姿态关键点 dump（脱敏，仅坐标不含图像）
    if predictions.get("pose_keypoints"):
        refs.append({"kind": "pose_keypoints", "ref": ".../keypoints.json", ...})
    # 高风险事件附加脱敏截图（跌倒/坠床/抽搐）
    if posture in ("falling", "lying_edge", "seizing") or fall_score > 0.5:
        refs.append({"kind": "image", "ref": ".../frame_desensitized.jpg", ...})
    return refs
```

原始视频留边缘端，仅上传指针，符合隐私合规。

## 4.5 场景驱动设计

### 4.5.1 状态机

场景驱动器 `scenario.py` 实现 4 阶段状态机，按 `SCENARIO_PROFILE` 环境变量配置场景列表：

```
idle -> started -> sustained -> recovering -> idle
```

- `started`：第 1 tick 启动
- `sustained`：第 2 tick 起持续
- `recovering`：达到 duration_ticks 后恢复
- `idle`：恢复 1 周期后结束，轮转到下一个场景

### 4.5.2 3 床 12 场景编排

| 床位 | 场景配置 | 侧重 |
|---|---|---|
| B01 | fall_suspected + nurse_call + fall_prediction + seizure | P1 紧急救护 |
| B02 | bed_leave + night_wandering + long_still + bedsore_risk | P2 长时监护 |
| B03 | environment_anomaly + door_departure + abnormal_posture + device_fault | P3 环境设备 |

场景驱动器向各适配器注入状态（`get_camera_state()`/`get_bed_state()` 等），适配器据此覆盖默认值，模拟真实传感器读数。

## 4.6 断网自治设计

### 4.6.1 SQLite 缓存三表

```sql
observations(id, ward_id, node_id, bed_id, source_type, data, quality, timestamp, synced)
safety_events(id, event_id, ward_id, ..., payload, occurred_at, synced)
node_health(id, node_id, status, metrics, timestamp, synced)
```

`synced` 字段标记是否已成功上报云端。

### 4.6.2 写入-发布-补传流程

```
正常模式：
  融合引擎产出事件
    -> 写入 SQLite (synced=0)
    -> MQTT 发布 QoS 1
    -> 收到云端 PUBACK
    -> 更新 SQLite synced=1

离线模式：
  写入 SQLite 持续累积 (synced=0)
  本地告警持续触发

恢复模式：
  sync_offline_data() 读取 synced=0 的事件
  按时间序批量补传（limit=50）
  成功后 mark_events_synced()
  云端按 event_id 去重，丢弃重复
```

### 4.6.3 health 心跳

每 10 周期发布一次 health，携带 `buffered_events`（未同步事件数），云端据此展示节点状态。断网期间 buffered_events 持续增长，恢复后归零。

## 4.7 边缘端实现

### 4.7.1 主控程序核心代码

```python
class EdgeAgent:
    def run(self) -> None:
        self.mqtt.connect()
        while self.running:
            # 1. 推进场景状态机
            self.scenario.tick()
            # 2. 采集观测
            observations = self._collect_observations()
            # 3. 摄像头推理
            cam_obs = next((o for o in observations if o.source_type == "camera"), None)
            inference_result = self.inference.run(cam_obs)
            # 4. 事件融合
            events = self.fusion.fuse(observations, inference_result)
            # 5. 发布事件
            self._publish_events(events)
            # 6. 每 10 周期发布健康心跳
            cycle += 1
            if cycle % 10 == 0:
                self._publish_health()
            # 7. 同步离线缓存
            self.sync_offline_data()
            time.sleep(self.tick_seconds)
```

### 4.7.2 MQTT 下行回调

```python
# 告警确认
def handle_ack(self, envelope): ...

def handle_model_deploy(self, envelope, action="deploy"):
    if action == "rollback":
        self.inference.rollback()
    else:
        self.inference.load_model(model_name, model_version)
    self._publish_health()  # 上报新 model_version
```
