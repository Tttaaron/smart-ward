## 二、启动与构建

### 2.1 本地开发

```bash
cd cloud-frontend
npm install          # 安装依赖（含 tailwindcss / postcss / autoprefixer）
npm run dev          # Vite dev server，默认端口 5174，/api 与 /ws 代理到 localhost:8001
```

Vite 代理：`/api -> http://localhost:8001`，`/ws -> ws://localhost:8001`。
本地联调时需先启动 `cloud-backend`（FastAPI :8000，经容器映射为 8001）与 MQTT Broker。

### 2.2 Docker 构建与访问

```bash
# 在仓库根目录
docker compose build cloud-frontend
docker compose up -d cloud-frontend
# 访问 http://localhost:8081
```

镜像两阶段构建：
- Stage 1 `node:20-alpine`：`npm install` + `npm run build`
- Stage 2 `python:3.11-slim`：运行 `proxy.py`，同时提供静态文件、`/api/*` 反代、`/ws` 代理

> **注意**：`package-lock.json` 与 `package.json` 必须保持一致。
> 本次修复前 lockfile 为 0.1.0 旧版，缺失 `element-plus`、`tailwindcss`、`postcss`、`autoprefixer`，已重新生成（详见 §2.3 构建日志）。

## 三、页面操作步骤

### 3.1 病床卡片与推理链路

1. 左侧第一列展示 W-01 病区三张病床卡片。
2. 每张卡片在“风险标签”行展示：
   - **推理链路徽章**：`⚡ 边缘`（绿）/ `☁️ 云端`（蓝）/ `🔁 协同`（橙），取该床最新事件的路由；
   - **节点网络徽章**：`在线`（绿）/ `降级`（橙）/ `离线`（红）。
3. 卡片底部展示节点当前**模型版本**（如 `1.0.0-q4`）。
4. 点击“监护”按钮打开该床隐私监护浮窗。

### 3.2 事件面板与处置

1. 中间第二列为“护理告警与呼叫中心”。
2. 每张事件卡展示：
   - 优先级 `P1/P2/P3`、事件类型中文名、**route 链路徽章**、**超时/降级徽章**（橙色虚线，`云端超时·边缘回退` 等）；
   - 床位、AI 置信度、节点网络徽章；
   - 第三行性能条：`模型`、`边缘推理`、`TTFT`、`云端延迟`、`内存`；
   - 底部 `trace` 短标识（取 trace_id 或 event_id 前 12 位）。
3. 状态徽章映射：`待处置 / 已通知 / 确认到场 / 已归档 / 判定误报 / 升级上报`。
4. 处置按钮：`立即到场`、`确认处置`、`标记误报`、`科室升级`（对应 acknowledge / resolve / false_positive / escalate）。
5. 顶部筛选：`全部 / P1特急 / 待到场 / 超时/降级 / 已归档`。

### 3.3 事件详情与链路追踪

1. 点击任意事件卡片，右侧滑出 **EventDetailDrawer**。
2. 抽屉内容：
   - **推理链路摘要**（边缘/云端/协同 + 说明文字）；
   - **event_id / trace_id / node_id**，trace 标识可一键复制，用于截图标注与跨模块回查；
   - **性能指标四宫格**：边缘推理耗时、TTFT 首token、云端往返延迟、峰值内存；
   - **模型名称 / 版本 / 置信度**；
   - **时间线**：发生 / 确认 / 归档；
   - **规则命中、证据引用、附加明细（details 原始 JSON）**；
   - **处置记录**：每次操作的动作、操作人、时间。

### 3.4 系统状态栏与异常提示

顶栏下方常驻状态条，从左到右：

| 状态芯片 | 判定 | 视觉 |
| --- | --- | --- |
| 云端链路 | WebSocket 连接态 | 在线=绿 / 连接中、重连N次=橙 / 离线=红（呼吸闪烁） |
| 云端 API | REST 健康轮询 | 正常=绿 / 不可用=红 |
| 边缘节点 | online_nodes/total_nodes | 全在线=绿 / 部分离线=橙 |
| 离线缓存 | nodes.buffered_events 合计 | >0 时橙色高亮，显示“N 条待补传” |
| MQTT | 派生自节点在线/API 健康 | 在线=绿 / 未知=灰 |
| 最近断开 | ws.disconnectedAt | 灰色信息芯片 |

**横幅提示**（演示核心）：
- **断网**：云端链路进入 reconnecting/disconnected 时，出现橙色横幅“⚠️ 云端链路中断 · 边缘继续本地值守”，并显示第 N 次重连；
- **恢复**：链路重新 connected 时，出现绿色横幅“✅ 云端链路已恢复”，显示恢复时间、累计重连次数、补传条数，6 秒后自动淡出，可手动关闭。

### 3.5 调试注入台

点击右下角 `⚡ 调试注入` 展开面板：

1. 选择目标床位 `B01/B02/B03`；
2. **推理链路**：`⚡ 边缘` / `☁️ 云端` / `🔁 协同` —— 决定注入事件的 `details.route` 与模型（边缘 qwen2.5-1.5b / 云端 qwen2.5-14b）；
3. **模拟网络状态**：`在线` / `降级` / `断网` —— 决定 `details.network` 与降级标记；
4. 可勾选 **“模拟云端超时 → 边缘回退”**；
5. 调节置信度；
6. 点击任一事件类型按钮注入。

### 3.6 模型管理与环境控制

- 顶栏“🧠 模型管理”：查看模型版本状态（草稿/验证中/已发布…），对已发布模型输入节点 ID 下发；
- 左列底部“🌡️ 环境联动控制”：开关空调/灯光/新风，指令经 `POST /api/env/control` 下发。

## 五、异常场景演示步骤

### 5.1 云端超时 → 边缘回退

1. 打开调试注入台，勾选“模拟云端超时 → 边缘回退”；
2. 任选链路注入事件；
3. 事件卡片出现橙色虚线徽章 `云端超时·边缘回退`，右侧橙色提示条；
4. 点击卡片进入详情，`附加明细` 中可见 `state_fallback: timeout` 与回退说明；
5. 顶部筛选切到“超时/降级”可单独列出。

### 5.2 断网 → 离线缓存 → 恢复补传

1. 注入台选网络状态 **断网** 后注入 2~3 条事件（或直接停掉 `cloud-backend` 容器）；
2. 观察系统状态栏：云端链路红、云端 API 红，出现断网横幅“边缘继续本地值守”；
3. 事件仍可通过本地已缓存数据展示，页面不出现空白；
4. 恢复后端（重启容器）后，云端链路转绿，出现恢复横幅显示补传条数。

### 5.3 MQTT 重连

1. 停掉 `mqtt-broker` 容器，观察云端 API 仍可能正常但节点离线（MQTT 芯片变未知/降级）；
2. 重启 `mqtt-broker`，边缘节点重连后 `node_health` 推送，节点在线数恢复。

> 说明：断网/重连演示依赖真实 Broker 与后端容器，录制前请先按 §2.2 启动完整 `docker compose up -d`。

## 七、联调字段说明（与 P1/P7 的契约）

前端展示依赖的字段（契约统一口径，见任务书 §1.3“接口先行”）：

| 字段 | 来源 | 前端用途 |
| --- | --- | --- |
| `event_id` | 事件主键（REST/WS） | 卡片主键、详情查询 |
| `trace_id` | `details.trace_id` / 事件顶层 | 链路追踪标识、截图标注 |
| `route` | `details.route`（edge/cloud/hybrid） | route 徽章判定 |
| `model_name / model_version` | REST `/api/events` | 模型展示 |
| `inference_ms` | REST `/api/events` | 边缘推理耗时 |
| `ttft_ms` | `details.ttft_ms` | TTFT 首token |
| `cloud_latency_ms` | `details.cloud_latency_ms` | 云端往返延迟 |
| `memory_mb` | `details.memory_mb` | 峰值内存 |
| `network` | `details.network`（online/degraded/offline） | 网络状态徽章 |
| `state_fallback` | `details.state_fallback`（timeout/cloud_unavailable） | 超时/降级徽章与筛选 |
| `state` | REST/WS | 处置状态（new/notified/acknowledged/resolved/false_positive/escalated） |

> 前端按“字段存在则展示，不存在则显示 —”设计，缺失字段不影响页面渲染，保证“不出现空白、重叠或无法区分的状态”。
