## 关键行为确认

1. **云端去重**：同 event_id 多次 request 仅推理 1 次，其余返回缓存（dedup_ttl=300s）。
2. **响应幂等**：pending 消费后进入 finished 缓存，重复 response 被 `status=duplicate` 忽略。
3. **非法 judgment**：`judgment∉{confirm,reject,escalate}` 时识别为 invalid，回退边缘原始判断（`fallback_edge/reason=invalid_judgment`），事件保持 `state=new` 不被污染。
4. **未知 event**：无 pending 且不在 finished 缓存的响应被 `status=unknown` 忽略，不落库。
5. **trace 校验**：event_id 匹配但 trace_id 不匹配时 `status=trace_mismatch` 拒绝消费 pending，不按 completed 采纳。
6. **超时回退与自治保持**：云端不可用时 timeout worker 触发 `fallback_edge/reason=timeout`，本地边缘判断保留，事件不丢失（SQLite 全部落库）；云端持续异常时 TaskRouter 自适应降低路由阈值（0.95→0.40，日志 `云端连续失败，降低边缘阈值至 …`），自动转本地自治。
7. **恢复**：云端恢复后新事件直接正常走云端（completed/confirm）；本场景 Broker 全程在线，事件上报均成功（synced=1），无未同步离线队列遗留。

## 说明

- 阶段4 的 20 条未知 event 响应发出时 P1 edge-agent 离线，故以 **SQLite 0 条落库** 为核心证据；"在线逐条忽略 unknown"行为已由阶段1 实证（20 次 `status=unknown`）。
- 数量为 20（任务书部分场景写 25/28）：由 P6/P1 协商对齐后的实际执行数，结论不受影响。
- 阶段3/5 因边缘自适应降阈值，单批不足 20 时以重启 edge-agent 补足（两批累计）。
