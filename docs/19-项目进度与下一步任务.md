## 一、项目总体定位

面向赛事交付的智慧病房云边端协同系统。复用智能教室已验证的 Vue + FastAPI + MQTT + MySQL + SQLite + Docker Compose 技术路线，领域模型、数据契约、事件闭环、边缘推理与协同训练面向病房安全监护重新设计。

- 范围：1 病房（W-01）× 3 床（B01~B03）
- 事件：13 类安全事件（跌倒/坠床/抽搐/离床/夜间徘徊/长时间静止/压疮/异常体态/设备故障/门区异常/环境异常/护士呼叫/交接班）
- 服务：8 个 Docker Compose 服务（mqtt-broker / mysql / cloud-backend / training-coordinator / cloud-frontend / cloud-llm-service / diffusion-service / 3×edge）
- 代码规模：约 2.9 万行 + 文档约 1.2 万行；Git 共 68 提交，4 人协作
- 里程碑：最终提交 8/31 23:59

### 7.2 容错集成测试 阶段1–6 全部通过（8/25–26）

| 阶段 | 场景 | 核心结果 |
|---|---|---|
| 1 重复 request 去重 | 20 相同 request | 云端 requests=1 / duplicates=19 / responses=20；边缘不建新事件 |
| 2 重复 response 幂等 | 19 次原样重放 + 首条真实 | 仅首条生效（19×`status=duplicate` 忽略）；SQLite 仅 1 条 |
| 3 非法 judgment | 20 条 `judgment=bogus` 拦截响应 | 20/20 `fallback_edge/invalid_judgment`、state=new、**0 误判 completed** |
| 4 未知 event | 20 个伪造 event_id 响应 | SQLite **落库 0 条**；后续真实事件正常处理不受干扰 |
| 5 trace 不匹配 | 20 条错误 trace 响应 | 20/20 `status=trace_mismatch`；SQLite **completed=0** / fallback_edge=20 |
| 6 云端不可用/超时回退+恢复 | 无响应→timeout worker 回退→云端恢复 | **25/25 fallback_edge/reason=timeout，事件未丢失**；恢复后正常 completed，synced=0 遗留=0 |

附加观察：云端持续异常时 TaskRouter 自适应降低路由阈值（0.95→0.40，`云端连续失败，降低边缘阈值至 …`），自动转本地自治——支撑"断网/异常时基本业务保持率 ≥90%"指标。

正式归档：`docs/evidence/20260825_fault_test_stage1-6/`（总结 + 各阶段 SQLite 查询 / 边缘日志 / MQTT 抓包共 23 文件）；过程文件与中间 zip 在 `docs/temp-evidence/`（不入库）。
