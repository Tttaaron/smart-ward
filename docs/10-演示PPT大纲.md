## 第2页：项目背景与痛点

**内容**：
- 配图：夜间病房护士站空无一人，床位异常无人察觉
- 四个痛点：
  - 🚨 **跌倒难发现**：老人/术后患者跌倒，夜间护士巡房间隔长，黄金救助期易错过
  - 🛏️ **离床风险高**：坠床、夜间徘徊无法实时告警
  - 📋 **交接班信息断层**：口头交接易遗漏，无结构化摘要

**讲稿**：
> "病房里最让人揪心的是这四类场景：患者跌倒却没人发现，老人夜间离床徘徊可能再次跌倒，交接班信息全凭口述。现有方案要么纯人工巡房、要么纯云端方案断网即瘫痪。我们想用边缘计算 + 多源融合解决这些问题。"

## 第3页：解决方案概述

**内容**：
- 核心理念图：**边缘自治 + 云边协同 + 多源融合 + 联邦学习**
- 一句话：让每张床位的"小电脑"自己看懂患者状态并秒级告警，云端护士站集中处置与协同训练
- ASCII 示意：
  ```
  摄像头 + 床垫 + 环境 ─┐
                              ├─> 边缘融合 ─> 事件 ─> 云端护士站
         Orange Pi 5 (NPU) ───┘                      │
              ↑                                     │
         联邦训练 <─────────────────────────────────┘
  ```

**讲稿**：
> "我们的方案是：在每张床位部署一台 Orange Pi 5 边缘主机，融合摄像头、床垫压力、环境三路传感器，本地秒级识别跌倒、坠床、离床等 13 类事件；事件通过 MQTT 上报云端护士站集中处置；误报样本回流云端，通过联邦学习持续优化边缘模型。"

## 第5页：边缘代理设计

**内容**：
- 边缘代理内部结构图：
  ```
  3 类采集适配器 ─┐
   camera        ├─> 融合引擎 ─> 推理引擎 ─> 事件
   bed_sensor    ─┤       │                  │
                        └─> SQLite 缓存 ───┘
   environment   ─┘
  ```
- 关键参数：
  - YOLOv8n-pose INT8 量化 ~6MB
  - NPU 推理 15-30 FPS
  - 4 源融合降低误报

**讲稿**：
> "边缘代理是本项目最核心的部分。它有 3 类采集适配器：摄像头用 OpenCV 读帧送 YOLOv8n-pose 推理姿态，床垫压力由 ESP32 通过 MQTT 上报，环境是独立适配器。融合引擎把多源观测合并，按规则引擎产出事件。模型只有 6MB，NPU 推理 15 到 30 帧，满足实时性。"

## 第7页：MQTT 通信契约

**内容**：
- MQTT 主题树：
  ```
  上行：ward/{ward_id}/node/{node_id}/{observation,event,health}
  下行：ward/{ward_id}/alert/{event_id}/ack
        node/{node_id}/{config/set, model/deploy, model/rollback}
  训练：training/{job_id}/node/{node_id}/{command,update}
  ```
- 可靠性三件套：QoS 1 + SQLite 缓存 + event_id 去重

**讲稿**：
> "通信层我们用 MQTT，主题树按 病房-节点-消息类型 分层。可靠性靠三件套：QoS 1 保证至少一次送达，边缘 SQLite 缓存保证断网不丢，event_id 全局唯一保证云端去重。这套方案不依赖任何平台，Docker Compose 和未来的 KubeEdge 都能用。"

## 第9页：事件闭环演示

**内容**：
- 事件状态机图：
  ```
  new -> notified -> acknowledged -> resolved
                     │         │
                     └> false_positive / escalated
  ```
- 截图：护士站收到 P1 跌倒告警 -> 点击"到场" -> 填写处置结果 -> 事件转 resolved

**讲稿**：
> "这是事件闭环演示。边缘端检测到跌倒，生成 P1 事件上报云端，护士站告警闪烁。护士点击'到场'进入处置中，填写处置结果后事件转 resolved。如果判断是误报，标记 false_positive 会回流到训练数据集；如果情况严重可以升级 escalated 通知值班医生。每次操作都写审计表。"

## 第10页：断网自治演示

**内容**：
- 断网流程图：
  ```
  断网 -> 边缘继续本地推理 -> 事件写入 SQLite (synced=0)
       -> 恢复网络 -> 按序补传 -> 云端按 event_id 去重
  ```
- 现场演示步骤提示（docker network disconnect / connect）

**讲稿** + **操作**：
> "现在演示最关键的断网自治。我断开 edge-bed-01 的网络，大家看云端，节点状态变成 offline。但我看边缘日志，它还在持续识别姿态、还在产生事件，只是事件先写本地 SQLite。现在我恢复网络，看，缓存的事件按时间序补传上来了，云端按 event_id 去重，没有任何重复告警。这就是边缘自治 + 业务层可靠性的价值。"

## 第14页：协同训练规划

**内容**：

  ```
  阶段 A：同步 FedAvg（基线）
  ```

- 创新点：自研框架，体现技术原创性

**讲稿**：
> "协同训练是本项目的核心创新点。我们自研联邦学习框架，不依赖 Flower 等现成框架。三阶段演进：先做同步 FedAvg 作为基线，再做半异步陈旧度加权应对网络抖动，最后做异常剔除和全链路日志。误报样本脱敏后回流云端，用扩散模型生成困难样本扩充数据集，再触发新一轮联邦训练，新模型通过 MQTT 灰度下发到边缘端。整个闭环不共享原始视频，符合病房隐私要求。"

## 第15页：创新点

**内容**：醒目展示五大创新点
1. ✨ **边缘多源融合**：摄像头 + 床垫 + 环境三源融合，单一传感器误报率降一个数量级

**讲稿**：
> "我们的创新点有五个。最核心的是边缘多源融合--靠单一摄像头或单一床垫都容易误报，三源融合后误报率能降一个数量级。其次是 13 类事件状态机闭环、自研联邦学习框架、平台无关的断网自治，以及从教室到病房的复用智慧。这些创新点都是我们团队从零设计的。"
