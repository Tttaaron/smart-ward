## 6.1 MQTT 主题树设计

系统采用 MQTT 协议作为云边通信中枢，主题树按"上行/下行/训练"三类隔离设计。

### 6.1.1 主题树全貌

```
# ── 上行：边缘 -> 云端 ──
ward/{ward_id}/node/{node_id}/observation      # 多源观测数据（摄像头/床位/环境）
ward/{ward_id}/node/{node_id}/event             # 安全事件（跌倒/离床/呼叫）
ward/{ward_id}/node/{node_id}/health            # 节点健康心跳

# ── 下行：云端 -> 边缘 ──
ward/{ward_id}/alert/{event_id}/ack             # 告警确认/处置/升级
node/{node_id}/config/set                        # 节点配置下发（环境控制：ac/light/fresh_air）
node/{node_id}/model/deploy                      # 模型版本下发（灰度）
node/{node_id}/model/rollback                    # 模型回滚

# ── 训练链路（与实时业务隔离）──
training/{job_id}/node/{node_id}/command        # 训练指令
training/{job_id}/node/{node_id}/update         # 梯度/权重上报
training/{job_id}/status                         # 训练任务状态
```

**图 6-1 MQTT 主题树结构**

### 6.1.2 主题设计原则

| 原则 | 说明 |
|---|---|
| **层级化** | `ward/{ward_id}/node/{node_id}/{type}` 按病区-节点-类型分层，支持通配订阅 |
| **上下行隔离** | 上行用 `ward/...` 前缀，下行用 `node/...` 前缀，权限可分离 |
| **训练隔离** | 训练链路用独立 `training/` 前缀，不与实时告警业务争抢带宽 |
| **通配订阅** | 云端用 `ward/+/node/+/{type}` 一次订阅所有节点 |

### 6.1.3 云端订阅清单

```python
# cloud-backend/app/mqtt_handler.py
topics = [
    ("ward/+/node/+/observation", 1),  # 所有节点的观测
    ("ward/+/node/+/event", 1),        # 所有节点的安全事件
    ("ward/+/node/+/health", 1),       # 所有节点的健康心跳
    ("ward/+/alert/+/ack", 1),         # 告警确认回环
]
```

### 6.1.4 边缘端订阅清单

```python
# edge-agent/src/mqtt_client.py
topics = [
    (f"ward/{ward_id}/alert/+/ack", 1),        # 本病区的告警确认
    (f"node/{node_id}/config/set", 1),          # 本节点的环境控制
    (f"node/{node_id}/model/deploy", 1),        # 本节点的模型部署
    (f"node/{node_id}/model/rollback", 1),      # 本节点的模型回滚
]
```

## 6.2 消息信封设计

### 6.2.1 通用信封结构

所有 MQTT 消息外层必须符合 `envelope.json` 信封结构：

```json
{
  "message_id": "uuid-v4",
  "event_id": "uuid-v4 或 null",
  "schema_version": "v1",
  "occurred_at": "2026-07-27T08:30:00Z",
  "source": "edge:EDGE-W01-B01",
  "trace_id": "uuid-v4",
  "payload": { ... }
}
```

**表 6-1 信封字段说明**

| 字段 | 类型 | 说明 |
|---|---|---|
| `message_id` | string(uuid) | 消息唯一 ID，消费端按此去重 |
| `event_id` | string(uuid) \| null | 关联的事件 ID（非事件消息为 null） |
| `schema_version` | string | 契约版本，当前 `v1` |
| `occurred_at` | string(iso8601) | 事件发生时间（UTC，Z 结尾） |
| `source` | string | 来源标识，如 `edge:EDGE-W01-B01` / `cloud` / `nurse-station` |
| `trace_id` | string | 跨服务追踪 ID，便于日志关联 |
| `payload` | object | 业务数据，结构见各消息 Schema |

### 6.2.2 六份 JSON Schema 清单

| Schema 文件 | 主题 | 用途 |
|---|---|---|
| `envelope.json` | （通用） | 通用消息信封 |
| `observation.json` | `ward/+/node/+/observation` | 多源观测数据上报 |
| `safety_event.json` | `ward/+/node/+/event` | 安全事件上报（13 类） |
| `node_health.json` | `ward/+/node/+/health` | 节点健康心跳 |
| `alert_ack.json` | `ward/+/alert/+/ack` | 告警确认/处置/升级指令 |
| `model_deploy.json` | `node/+/model/deploy` | 模型版本下发 |

> 所有 Schema 用 `additionalProperties: false` 严格校验，是前后端联调的**唯一标准**，不依赖代码注释或口头约定。

## 6.3 事件数据模型

### 6.3.1 13 类事件类型与优先级

| event_type | 中文名 | 优先级 | 默认来源 | 说明 |
|---|---|---|---|---|
| `fall_suspected` | 疑似跌倒 | P1 | 边缘端 | 摄像头姿态=falling + fall_score>0.5 + 床位离床 |
| `nurse_call` | 护士呼叫 | P1 | 前端/按钮 | 护士呼叫按钮触发，边缘端可透传 |
| `fall_prediction` | 坠床预警 | P1 | 边缘端 | 床位占床 + 姿态=lying_edge + fall_score 超阈值（事前预警） |
| `seizure` | 抽搐检测 | P1 | 边缘端 | tremor_score 超阈值，可能是癫痫发作 |
| `bed_leave` | 离床 | P2 | 边缘端 | 床位 absence_seconds ≥ 阈值（默认 30s） |
| `door_departure` | 门区异常离开 | P2 | 边缘端 | 门磁 open + 摄像头检测到人离开区域 |
| `night_wandering` | 夜间徘徊 | P2 | 边缘端 | 夜间时段（22:00-06:00）+ 持续离床 |
| `long_still` | 长时间静止 | P2 | 边缘端 | 同一体位持续超阈值（默认 5 分钟） |
| `abnormal_posture` | 异常体态 | P2 | 边缘端 | posture 命中 curled/leaning/grabbing_chest |
| `environment_anomaly` | 环境异常 | P3 | 边缘端 | 温度/CO₂/光照超阈值 |
| `bedsore_risk` | 压疮预防 | P3 | 边缘端 | 同一体位持续超阈值（默认 2 小时） |
| `device_fault` | 设备故障 | P3 | 边缘端 | 传感器 quality.degraded 持续超阈值（默认 60 秒） |
| `node_offline` | 节点失联 | P3 | 云端 | 边缘节点健康心跳超时 |

### 6.3.2 事件状态机

事件采用 6 态状态机，确保处置闭环：

```
                ┌─────────────┐
                │     new     │  边缘端新生成
                └──────┬──────┘
                       │ 云端收到并入库
                       ▼
                ┌─────────────┐
                │   notified  │  已推送到护士站
                └──────┬──────┘
                       │ 护士点击"到场"
                       ▼
                ┌─────────────┐
     ┌──────────│ acknowledged│  已确认（开始处置）
     │           └──────┬──────┘
     │                  │
     │     ┌────────────┼────────────┐
     │     ▼            ▼            ▼
     │ ┌───────┐  ┌──────────┐  ┌───────────┐
     │ │resolved│  │false_    │  │escalated  │
     │ │       │  │positive  │  │           │
     │ │已处置 │  │误报      │  │升级       │
     │ └───────┘  └──────────┘  └───────────┘
```

**图 6-2 事件状态机**

**表 6-2 状态转换规则**

| 当前态 | 允许的 action | 目标态 |
|---|---|---|
| `new` | （云端自动） | `notified` |
| `notified` | acknowledge | `acknowledged` |
| `notified` | resolve | `resolved` |
| `notified` | false_positive | `false_positive` |
| `notified` | escalate | `escalated` |
| `acknowledged` | resolve | `resolved` |
| `acknowledged` | false_positive | `false_positive` |
| `acknowledged` | escalate | `escalated` |
| `resolved` / `false_positive` / `escalated` | （终态） | - |

### 6.3.3 事件字段规范

事件 payload 对齐 `contracts/safety_event.json`，核心字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `event_id` | uuid | 是 | 事件唯一 ID（边缘端 UUID4 生成） |
| `ward_id` | string | 是 | 病区 ID |
| `node_id` | string | 是 | 边缘节点 ID |
| `bed_id` | string | 是 | 床位 ID |
| `event_type` | enum | 是 | 13 类之一 |
| `priority` | enum | 是 | P1/P2/P3 |
| `state` | enum | 是 | 见 §6.3.2 状态机 |
| `occurred_at` | iso8601 | 是 | 事件发生时间（UTC） |
| `detected_at` | iso8601 | 是 | 边缘端检测到的时间 |
| `confidence` | float | 是 | 置信度 0~1 |
| `model.model_name` | string | 是 | 模型名 |
| `model.model_version` | string | 是 | 语义化版本 |
| `model.inference_ms` | int | 是 | 推理耗时毫秒 |
| `evidence_refs` | array | 是 | 证据引用（脱敏截图/片段指针） |
| `rule_hits` | array | 否 | 命中的规则列表 |
| `details` | object | 否 | 事件特有补充字段 |

### 6.3.4 evidence_refs 证据引用结构

`evidence_refs` 是隐私合规设计的核心：原始视频留边缘端，仅上传脱敏证据指针。

```json
"evidence_refs": [
  {
    "kind": "pose_keypoints",
    "ref": "/app/evidence/EDGE-W01-B01/2026-07-27T08:30:00Z/keypoints.json",
    "taken_at": "2026-07-27T08:30:00Z"
  },
  {
    "kind": "image",
    "ref": "/app/evidence/EDGE-W01-B01/2026-07-27T08:30:00Z/frame_desensitized.jpg",
    "taken_at": "2026-07-27T08:30:00Z"
  }
]
```

| kind | 说明 | 触发条件 |
|---|---|---|
| `image` | 脱敏截图（遮蔽面部） | 高风险事件（跌倒/坠床/抽搐） |
| `clip` | 裁剪片段指针 | 事件前后 5 秒视频 |
| `sensor_dump` | 传感器原始数据 dump | 多源联调排查 |
| `pose_keypoints` | 17 关键点坐标（无图像） | 有 pose_keypoints 时 |

## 6.4 QoS 与可靠性

### 6.4.1 QoS 1 配置

所有 MQTT 消息使用 QoS 1（至少一次送达），配合业务层去重实现"恰好一次"语义：

| 层 | 机制 | 作用 |
|---|---|---|
| 传输层 | QoS 1 | 至少一次送达，断网时消息不丢 |
| 业务层 | `message_id` 去重 | 云端按 message_id 丢弃重复消息 |
| 业务层 | `event_id` 唯一约束 | 事件全局唯一，断网补传不产生重复告警 |

### 6.4.2 断网缓存与补传

```
边缘端事件流（正常）：
  融合引擎产出事件
    -> 写入 SQLite (synced=0)
    -> MQTT 发布 QoS 1
    -> 收到云端 PUBACK
    -> 更新 SQLite synced=1

断网场景：
  写入 SQLite 持续累积 (synced=0)
  本地告警持续触发（P1 本地置顶）
  恢复后按时间序补传
  云端按 event_id 去重，丢弃重复
```

**图 6-3 断网缓存与补传流程**

**表 6-3 可靠性三件套**

| 组件 | 实现位置 | 作用 |
|---|---|---|
| QoS 1 | `mqtt_client.py _publish(qos=1)` | 至少一次送达 |
| SQLite 缓存 | `database.py save_event(synced=0)` | 断网期间事件不丢 |
| event_id 去重 | `mqtt_handler.py _handle_event` 查重 | 补传产生的重复被丢弃 |
| synced 补传 | `main.py sync_offline_data()` | 恢复后按时序批量补传 |

### 6.4.3 时间格式

所有时间使用 **UTC ISO 8601**，`Z` 结尾：

```python
# 边缘端生成
datetime.now(timezone.utc).isoformat().replace("+00:00", "Z")
# 示例：2026-07-27T08:30:00.123456Z
```

云端存储 UTC，前端转本地时区显示。交接班摘要生成时按东八区（+08:00）转换班次时段。

### 6.4.4 重连机制

边缘端与云端均实现自动重连：

| 端 | 机制 | 实现 |
|---|---|---|
| 边缘端 | 后台线程重试 | `_connect_loop()` 每 5 秒重试 |
| 云端 | paho 原生退避 | `reconnect_delay_set(min=2, max=60)` 指数退避 |

## 6.5 通信安全

### 6.5.1 演示阶段（当前）

| 项 | 配置 | 说明 |
|---|---|---|
| MQTT 认证 | `allow_anonymous true` | 演示便捷，生产需关闭 |
| MQTT 加密 | 无 TLS | 演示内网，生产需 TLS |
| 前端鉴权 | 无 | 演示阶段开放 |
| 数据库密码 | 环境变量 | `.env.example` 提供模板 |

### 6.5.2 生产阶段加固

| 项 | 加固措施 |
|---|---|
| MQTT 认证 | 账号密码 + ACL（按 topic 限制读写） |
| MQTT 加密 | TLS 1.2+ 传输加密 |
| 前端鉴权 | JWT + 角色权限（nurse/charge_nurse/admin/observer） |
| 数据库 | 最小权限账号 + 密码 vault 管理 |
| 审计 | 所有操作进 `audit_logs` 表（已实现） |
| 隐私 | 患者匿名别名 + 原始视频留边缘端（已实现） |
