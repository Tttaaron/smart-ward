## 四、技术选型（最终确定）

### 4.1 大模型选型

| 层级 | 模型 | 规格 | 用途 |
|------|------|------|------|
| **边缘端** | Qwen2.5-1.5B-Instruct | GPTQ-Int4, GGUF格式, ~1.1GB | 事件语义增强、护理建议、离线决策、活动汇报 |
| **云端** | Qwen2.5-14B-Instruct | FP16/BF16, ~28GB (或AWQ 4bit ~8GB) | 复杂事件二次研判、全局决策、模型蒸馏教师 |

## 五、已完成的代码改造（详细）

### 5.1 新增模块：`edge-agent/src/llm_engine.py`（335行）

**功能**：LLM推理引擎，支持mock/real双模式

**核心类**：
- `LLMResponse` - 推理响应结构（text, ttft_ms, total_ms, tokens_generated, memory_mb）
- `LLMEngineMetrics` - 累计性能指标（avg_ttft_ms, peak_memory_mb等）
- `LLMEngine` - 推理引擎主类

**关键方法**：
```python
class LLMEngine:
    MODEL_NAME = "qwen2.5-1.5b-instruct"
    MODEL_VERSION = "1.0.0-int4"
    
    def __init__(self):  # 读取LLM_MODE/LLM_MODEL_PATH等环境变量
    def generate(self, prompt, system="", max_tokens=None) -> LLMResponse
    def _generate_real(self, prompt, system, max_tokens) -> LLMResponse  # llama.cpp流式
    def _generate_mock(self, prompt, system, max_tokens) -> LLMResponse  # 模板化响应
    def get_status(self) -> dict  # 用于health上报
```

**环境变量**：
- `LLM_MODE`: mock/real（默认mock）
- `LLM_MODEL_PATH`: GGUF模型文件路径
- `LLM_N_CTX`: 上下文窗口（默认2048）
- `LLM_N_GPU_LAYERS`: GPU卸载层数
- `LLM_MAX_TOKENS`: 最大生成token数（默认128）

### 5.2 新增模块：`edge-agent/src/llm_advisor.py`（370行）

**功能**：LLM应用层，提供三大能力

**核心类**：
- `EventEnhancement` - 事件增强结果（summary, advice, urgency, llm_response）
- `OfflineDecision` - 离线决策结果（prioritized_events, emergency_actions）
- `LLMAdvisor` - 决策顾问主类

**关键方法**：
```python
class LLMAdvisor:
    def __init__(self, node_id, bed_id, ward_id)
    def enhance_event(self, event_dict, observations) -> EventEnhancement  # 事件语义增强
    def nursing_advice(self, event_dict, patient_context) -> str  # 护理建议
    def offline_decision(self, pending_events) -> OfflineDecision  # 离线自治决策
    def should_offload_to_cloud(self, event_dict) -> bool  # 是否卸载云端
    def get_status(self) -> dict
```

**路由策略**（should_offload_to_cloud）：
- 置信度 < 0.7 → 云端
- P1事件且置信度 < 0.85 → 云端复核
- 罕见事件(seizure/bedsore/abnormal_posture)且置信度 < 0.8 → 云端

### 5.3 新增模块：`edge-agent/src/task_router.py`（368行）

**功能**：云边协同任务路由器

**核心类**：
- `ComputeTarget` - 枚举：EDGE/CLOUD/HYBRID
- `NetworkState` - 枚举：CONNECTED/DEGRADED/DISCONNECTED
- `RoutingDecision` - 路由决策结果
- `RouterMetrics` - 累计指标
- `TaskRouter` - 路由器主类

**关键方法**：
```python
class TaskRouter:
    EVENT_COMPLEXITY = {  # 每种事件类型的复杂度权重
        "fall_suspected": 0.7, "seizure": 0.85, "bed_leave": 0.3, ...
    }
    
    def update_network_state(self, mqtt_connected, latency_ms=0)  # 每tick调用
    def route(self, event_dict) -> RoutingDecision  # 路由决策
    def detect_conflict(self, new_event) -> Optional[dict]  # 冲突检测
    def get_conflict_ratio(self) -> float  # 冲突比例（对齐<=5%指标）
    def record_cloud_result(self, event_id, success, latency_ms)  # 记录云端结果
    def get_status(self) -> dict
```

**路由公式**：
```
edge_score = 0.4*confidence + 0.3*(1-complexity) + 0.3*network_penalty
当 edge_score >= threshold(0.65) → 边缘处理
当 P1且confidence<0.85 → 混合模式
否则 → 云端处理
断网 → 强制边缘
```

**冲突检测**（CONFLICT_PAIRS）：
- bed_leave vs long_still
- fall_suspected vs abnormal_posture
- night_wandering vs long_still

## 十一、关键结论与决策记录

1. **场景合规**：智慧病房属于"智慧城市-智慧医疗"子领域，赛题"包括但不限于"，完全合规，不需要换场景
2. **技术路线**：Qwen2.5-1.5B(边缘) + Qwen2.5-14B(云端) + YOLOv8-pose(视觉) + MQTT(通信)
3. **核心叙事**：从"被动告警器"升级为"主动感知的AI护理助手"（持续活动监测+LLM语义汇报）
4. **得分策略**：优先T1+T2(40分技术效果)，其次T3+T5(20+25分)，最后T6(15分)
5. **第二场景**：暂不实施真实第二场景，用Docker模拟节点扩展证明"可扩展性"
6. **传感器精简**：搁置床垫/环境传感器，聚焦纯视觉AI + LLM
7. **模型不更换**：确定使用Qwen2.5系列（1.5B边缘 + 14B云端），不改为Qwen3
8. **mock优先**：开发阶段全部用mock模式，Docker演示可跑；实机部署时切real模式
