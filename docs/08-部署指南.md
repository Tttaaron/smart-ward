# 部署指南

> 智慧病房云边协同系统部署手册。覆盖本地 Docker Compose 一键启动、端侧 Orange Pi 5 烧录、ESP32 床垫传感器接入、云端护士站访问与常见问题排查。
> 对齐 `smart-ward/docker-compose.yml` 的 8 服务编排。

---

## 1. 环境要求

### 1.1 硬件要求

#### 云端（开发/演示机）
| 资源 | 最低要求 | 推荐配置 | 说明 |
|------|---------|---------|------|
| CPU | 4 核 | 8 核 | 同时跑 MQTT/MySQL/后端/前端/3 个边缘代理 |
| 内存 | 8 GB | 16 GB | MySQL + 3 edge-agent + 浏览器 |
| 磁盘 | 50 GB 可用 | 100 GB SSD | 镜像 + MySQL 数据 + 边缘 SQLite 缓存 |
| 网络 | 千兆 | 千兆 | 云边通信 + 护士站访问 |

#### 端侧（每张床位）
| 设备 | 型号 | 关键参数 | 用途 |
|------|------|---------|------|
| 边缘主机 | Orange Pi 5 | RK3588 6 TOPS NPU、8GB RAM | 边缘推理 + 本地缓存 |
| 摄像头 | 罗技 C920 | 1080p USB | 姿态识别输入源 |
| 床垫传感器 | ESP32 + FSR402 | Wi-Fi + 压力传感 | 在床/离床检测 |
| SD 卡 | 64 GB U3 | A2 级 | 系统 + Docker 镜像存储 |

> 单床位预算约 1400 元，3 床位总预算约 6900 元（含主机/摄像头/传感器/线缆）。

### 1.2 软件要求

| 软件 | 版本 | 用途 |
|------|------|------|
| Docker Desktop | 4.20+（含 Compose v2） | 容器运行与编排 |
| Git | 2.30+ | 代码拉取与版本管理 |
| Python | 3.10+ | 端侧 edge-agent / 训练调度脚本 |
| Node.js | 18 LTS | 前端构建（仅本地开发时需要） |
| 浏览器 | Chrome / Edge 最新版 | 访问护士站工作台 |
| balenaEtcher | 1.7+ | Orange Pi 5 SD 卡烧录 |
| mosquitto-clients | 2.0+ | MQTT 调试（mosquitto_pub/sub） |

> Windows 用户建议启用 WSL2 后端以提升 Docker 性能；Linux/macOS 直接安装 Docker Engine 即可。

## 2. Docker Compose 一键启动（推荐）

### 2.1 获取代码

```powershell
git clone <repository-url>
cd smart-ward
```

### 2.2 配置环境变量

```powershell
# 复制示例配置
Copy-Item .env.example .env   # Windows PowerShell
# cp .env.example .env          # Linux/macOS

# 按需修改 .env（默认值已可直接演示）
```

`.env.example` 全字段说明：

```ini
# ===== MySQL（云端事件中心）=====
MYSQL_ROOT_PASSWORD=smartward_root   # MySQL root 密码（演示用，生产必须改）
MYSQL_DATABASE=smart_ward             # 业务库名（init.sql 自动建表）
MYSQL_USER=smart_ward                 # 业务账号
MYSQL_PASSWORD=smartward_pass         # 业务密码

# ===== MQTT Broker =====
MQTT_BROKER=mqtt-broker               # 容器内主机名（Compose 网络内解析）
MQTT_PORT=1883                        # 容器内 MQTT 端口

# ===== 端口映射（与 docker-compose.yml 对齐）=====
# MQTT      1884 -> 1883
# MySQL     3308 -> 3306
# 后端 API  8001 -> 8000
# 训练调度  8002 -> 8000
# 护士站    8081 -> 80

# ===== 边缘节点默认参数（可在 docker-compose per-service 覆盖）=====
TICK_SECONDS=3                       # 边缘采集周期（秒），3 床统一
EVENT_DEDUPE_SECONDS=30              # 同类事件去重窗口（秒）

# ===== 演示阶段安全配置（生产环境必须收紧）=====
# MQTT 匿名访问，演示阶段开启；接入真实病房前需启用 ACL/TLS
MQTT_ALLOW_ANONYMOUS=true
```

### 2.3 构建并启动

```powershell
# 构建镜像并后台启动全部 8 个服务
docker compose up -d --build

# 查看启动状态
docker compose ps
```

## 4. 端侧部署（Orange Pi 5）

端侧用于真实硬件接入，当前演示阶段在 Docker 内用模拟数据，端侧部署为阶段二目标（对应方案书 §5.2）。

### 4.1 烧录 Ubuntu 22.04

1. 下载 Orange Pi 5 官方 Ubuntu 22.04 镜像（`orangepi5_ubuntu_jammy_desktop_xfce`）。
2. 用 balenaEtcher 烧录到 64GB SD 卡。
3. 首次启动后配置 Wi-Fi、时区、开启 SSH。

```bash
# 烧录完成后插入 Orange Pi 5，SSH 登录
ssh orangepi@<orangepi-ip>

# 更新系统
sudo apt update && sudo apt upgrade -y
```

### 4.2 安装 Docker

```bash
# 安装 Docker 引擎
curl -fsSL https://get.docker.com | sudo sh

# 将当前用户加入 docker 组（免 sudo）
sudo usermod -aG docker $USER
newgrp docker

# 验证
docker --version
docker compose version
```

### 4.3 拉取 edge-agent 镜像

```bash
# 方式一：从云端 registry 拉取（CI 推送后）
docker pull <registry>/smart-ward/edge-agent:latest

# 方式二：本地构建（拷贝源码到设备）
git clone <repository-url>
cd smart-ward/edge-agent
docker build -t smart-ward/edge-agent:latest .
```

### 4.4 启动单床位边缘代理

```bash
# 设置环境变量
export WARD_ID=W-01
export BED_ID=B01
export EDGE_NODE_ID=EDGE-W01-B01
export MQTT_BROKER=<云端主机IP>    # 例如 192.168.1.100
export MQTT_PORT=1884
export TICK_SECONDS=3
export SCENARIO_PROFILE=fall,nurse_call,fall_prediction,seizure

# 运行（真实摄像头模式下不走 scenario，由 adapter 直接读帧）
docker run -d --name edge-bed-01 \
  --restart unless-stopped \
  -e WARD_ID=$WARD_ID -e BED_ID=$BED_ID -e EDGE_NODE_ID=$EDGE_NODE_ID \
  -e MQTT_BROKER=$MQTT_BROKER -e MQTT_PORT=$MQTT_PORT \
  -e TICK_SECONDS=$TICK_SECONDS -e SCENARIO_PROFILE=$SCENARIO_PROFILE \
  -v /dev/video0:/dev/video0 --device /dev/video0 \
  -v edge-b01-data:/app/data \
  smart-ward/edge-agent:latest
```

### 4.5 USB 摄像头接入（OpenCV 读帧）

```bash
# 确认摄像头被识别
ls -l /dev/video0
# 输出应类似：crw-rw---- 1 root video 81, ... /dev/video0

# 测试 OpenCV 读帧
python3 -c "import cv2; cap=cv2.VideoCapture(0); print('OK' if cap.isOpened() else 'FAIL')"
```

`edge-agent/src/adapters/camera.py` 已预留 OpenCV 读帧入口：

```python
# 伪代码示意（实际实现见 edge-agent/src/adapters/camera.py）
import cv2
cap = cv2.VideoCapture(0)  # /dev/video0
ret, frame = cap.read()
# frame 送入推理引擎（YOLOv8n-pose INT8）
```

### 4.6 ESP32 床垫传感器接入

ESP32 + FSR402 通过 Wi-Fi 将压力值上报 MQTT：

1. ESP32 烧录 Arduino 固件（见 `edge-agent/firmware/`，后续补齐）。
2. 配置 Wi-Fi 与云端 MQTT 地址。
3. 每 1 秒读取 FSR402 模拟值，发布到 `ward/W-01/node/EDGE-W01-B01/bed_sensor`。
4. edge-agent 的 `bed_sensor.py` 适配器订阅并转换为 `occupied/absence_seconds`。

```cpp
// ESP32 上报伪代码
WiFiClient espClient;
PubSubClient client(espClient);
int fsr = analogRead(FSR_PIN);           // 0-4095
bool occupied = fsr > THRESHOLD;          // 压力阈值
char payload[64];
snprintf(payload, sizeof(payload),
         "{\"occupied\":%s,\"fsr\":%d}",
         occupied ? "true" : "false", fsr);
client.publish("ward/W-01/node/EDGE-W01-B01/bed_sensor", payload);
```

### 4.7 边缘模型部署（YOLOv8n-pose INT8）

```bash
# 将 6MB 的 INT8 量化模型放到设备
scp models/yolov8n-pose-int8.rknn orangepi@<ip>:~/edge-agent/models/

# edge-agent 启动时自动加载
docker run ... -v ~/edge-agent/models:/app/models \
  smart-ward/edge-agent:latest
```

预期指标：
- 模型大小：约 6 MB
- NPU 推理帧率：15-30 FPS（取决于分辨率）
- 单帧推理延迟：33-66 ms

## 5. 云端部署

云端 5 个服务（mqtt-broker / mysql / cloud-backend / training-coordinator / cloud-frontend）统一由 `docker-compose.yml` 编排，无需单独部署。

3. 端侧 Orange Pi 5 的 `MQTT_BROKER` 指向该地址。
4. 配置 Nginx 反向代理 + HTTPS（生产必须）。

## 10. 常见问题排查

### 10.1 容器起不来

**现象**：`docker compose ps` 某服务为 Exited 或 Restarting。

```powershell
# 查看具体错误
docker compose logs <service-name> --tail=50

# 常见原因与处理：
# 1) 端口冲突 -> netstat -ano | findstr "1884 3308 8001 8002 8081"
# 2) 镜像构建失败 -> docker compose build <service-name> --no-cache
# 3) MySQL 健康检查未通过 -> 见 10.4
# 4) 内存不足 -> docker stats 查看占用，关闭其他容器

# 彻底清理重建
docker compose down -v
docker system prune -a
docker compose up -d --build
```

### 10.2 MQTT 连不上

**现象**：edge-bed 容器日志反复 `ConnectionRefusedError`。

```powershell
# 1. 确认 mqtt-broker 已 Up
docker compose ps mqtt-broker

# 2. 确认 1884 端口监听
docker port mqtt-broker
# 应输出 1883/tcp -> 0.0.0.0:1884

# 3. 进入 edge 容器测试连通
docker exec -it edge-bed-01 sh
# 容器内：ping mqtt-broker（Compose 网络内 DNS 解析）

# 4. 检查 mosquitto.conf 是否允许匿名
cat mqtt-broker/mosquitto.conf
# allow_anonymous true（演示阶段）
```

### 10.3 前端空白页

**现象**：访问 `http://localhost:8081` 白屏或 `Cannot GET /`。

```powershell
# 1. 确认前端容器在运行
docker compose ps cloud-frontend

# 2. 确认 nginx 转发后端正常
docker exec cloud-frontend curl -s http://cloud-backend:8000/health
# 应返回 {"status":"ok"}

# 3. 浏览器 F12 查看 Console 与 Network 报错
#    - 若 WebSocket 连接失败：检查 /api 路径代理（nginx.conf）
#    - 若 CORS 报错：后端已默认放行，检查是否被反向代理改写

# 4. 前端容器重建（构建产物缓存问题）
docker compose up -d --build cloud-frontend
```

### 10.4 数据库不初始化

**现象**：MySQL 容器启动但 `SHOW TABLES` 为空。

```powershell
# 1. 确认 init.sql 挂载正确
docker exec mysql ls -la /docker-entrypoint-initdb.d/
# 应看到 init.sql

# 2. 原因：MySQL 只在首次启动（空数据卷）时执行 init.sql
#    若数据卷已存在旧数据，init.sql 不会重新执行

# 解决：删除数据卷后重新启动
docker compose down -v
docker compose up -d mysql
Start-Sleep -Seconds 30

# 验证
docker exec mysql mysql -u smart_ward -psmartward_pass smart_ward -e "SHOW TABLES;"
# 应看到 11 张表
```

### 10.5 边缘节点离线告警

**现象**：护士站显示节点 `offline`，`node_offline` 事件频发。

```powershell
# 1. 检查 edge 容器是否存活
docker compose ps edge-bed-01

# 2. 检查 health 心跳主题
mosquitto_sub -h localhost -p 1884 -t "ward/+/node/+/health" -v
# 应每 TICK_SECONDS（默认 3s）收到一条

# 3. 若心跳正常但云端仍判离线：
#    检查 cloud-backend 的健康超时阈值配置（默认 30s）
```
