# 上传规范

> 智慧病房云边协同系统代码与文档提交规范。覆盖 commit 格式、版本号规则、更新类别、分支策略、PR 流程与代码规范。
> 对齐 edge/docs/09-上传规范.md 模板，按病房团队 7 人协作场景细化。

---

## 1. Commit 格式模板

```
[版本号 类别] 更新概要
- 更新内容1
- 更新内容2
- ...
```

### 1.1 参数说明

#### 版本号
`v主版本.次版本.修订号`，如 `v1.2.0`。

#### 更新概要
一句话概括本次提交的核心目的，不超过 50 个字，如"新增跌倒事件多源融合规则"。

#### 更新内容
无序列表，逐条描述具体改动。每条以动词开头（如"新增""修复""调整""优化"），如"修复 MQTT 断网补传时 event_id 去重失效的问题"。

---

## 2. 更新类别

| 类别 | 含义 | 典型场景 |
|------|------|----------|
| `feat` | 新增功能 | 新增事件类型、新增 API、新增前端组件 |
| `update` | 功能更新 | 改进现有功能、性能优化、规则调整 |
| `fix` | 修复缺陷 | 解决 bug、异常报错、逻辑错误 |
| `refactor` | 架构重构 | 调整目录结构、重命名类/函数、优化可读性（不改变外部行为） |
| `docs` | 文档更新 | 新增/修改 README、部署指南、调研报告、骨架文档 |
| `test` | 测试相关 | 新增单元测试、补充边界用例、修复测试 |
| `chore` | 杂项工程 | 依赖升级、配置文件调整、CI 脚本、.gitignore |

> 与 edge 项目原 `update/debug/refactor/docs/test` 五类相比，本规范增加 `feat`（突出新功能）与 `chore`（区分工程杂项），更贴近 7 人协作的多类型提交。

---

## 3. 版本号规则

### 3.1 主版本号（v**X**.0.0）
- 不兼容的 API 或架构变更时递增
- 示例：从 Docker Compose 演进到 KubeEdge 部署、MQTT 主题树重构、事件状态机重新设计

### 3.2 次版本号（v1.**X**.0）
- 向下兼容的功能新增或重大改进时递增
- 示例：新增一类事件、新增 10 项智能功能之一、新增联邦训练半异步调度

### 3.3 修订号（v1.0.**X**）
- 向下兼容的问题修复或微调时递增
- 示例：修复跌倒检测误报、调整去重窗口、补全文档

## 5. 分支策略

### 5.1 分支模型

```
master            主干，始终可演示、可部署
  │
  ├── feature/edge-fall-prediction     新增坠床预警
  ├── feature/shift-summary            交接班摘要
  ├── feature/fedavg-async             半异步联邦训练
  ├── fix/mqtt-dedupe                 修复 MQTT 去重
  └── docs/deploy-guide               部署指南撰写
```

### 5.2 分支命名规范

| 前缀 | 用途 | 示例 |
|------|------|------|
| `master` | 主干，受保护 | master |
| `feature/` | 新功能开发 | feature/edge-seizure-detection |
| `fix/` | 缺陷修复 | fix/mqtt-reconnect |
| `docs/` | 纯文档更新 | docs/tech-report |
| `test/` | 测试用例补充 | test/fusion-edge-cases |
| `refactor/` | 重构 | refactor/adapters-split |
| `chore/` | 工程杂项 | chore/upgrade-deps |

分支名用小写 + 短横线分隔，不超过 40 字符。

### 5.3 分支生命周期

1. 从 `master` 切出功能分支
2. 开发 + 本地测试通过（17 edge-agent + 4 training 测试全绿）
3. 推送到远程，发起 PR
4. 至少 1 人 Code Review 通过
5. 合并到 `master`，删除功能分支

> `master` 分支受保护，禁止直接 push，必须走 PR。

## 6. PR 流程

### 6.1 提交 PR

1. 确保本地测试通过：
   ```powershell
   python -m unittest discover edge-agent/tests -v
   python -m unittest discover training-coordinator/tests -v
   ```
   说明：项目使用标准库 unittest（测试以 `unittest.TestCase` 子类组织），不依赖 pytest。两条命令均应输出 `Ran 17 tests` / `Ran 4 tests` 且 `OK`。
2. 提交时按 commit 模板填写完整信息。
3. 在 GitHub / GitLab 发起 Pull Request，目标分支 `master`。
4. PR 标题与 commit 概要保持一致，如 `[v0.2.0 feat] 新增坠床预警事件类型`。
5. PR 描述包含：
   - 改动概要
   - 关联的 issue（如有）
   - 测试结果（截图或日志）
   - 是否影响向后兼容

### 6.2 Code Review

- 至少 1 名团队成员 Review 通过方可合并。
- Review 关注点：
  - 是否对齐 MQTT 契约（contracts/）
  - 是否对齐事件字典（docs/00-事件字典.md）
  - 是否补齐对应单元测试
  - 中文注释是否完整
  - 是否引入硬编码密钥/真实患者信息
- Review 意见用 `nit:`（小问题）/ `question:`（疑问）/ `block:`（必须修改）前缀。

### 6.3 合并方式

- 优先 `Squash and merge`（保持 master 历史整洁，每个 PR 一个 commit）
- 大型 PR 用 `Rebase and merge`（保留原子提交）
- 禁用 `Create a merge commit`（避免合并节点污染历史）

## 7. 代码规范要求

### 7.1 Python（edge-agent / cloud-backend / training-coordinator）

- **Python 版本**：3.10+
- **类型标注**：函数参数与返回值必须标注类型
  ```python
  def detect_fall(observation: Dict[str, Any], threshold: float = 0.5) -> Optional[Event]:
      ...
  ```
- **中文注释**：模块、类、公开函数必须有中文 docstring
  ```python
  class FusionEngine:
      """多源融合引擎

      合并摄像头/床垫/输液/环境四路观测，
      按规则引擎产出 14 类安全事件。
      """
  ```
- **命名**：类用 PascalCase，函数与变量用 snake_case，常量用 UPPER_SNAKE
- **依赖**：第三方库写入 `requirements.txt` 并锁定版本
- **测试覆盖**：新增功能必须补单元测试，保持 17+4 测试全绿
- **异步**：MQTT 与 WebSocket 用 async，避免阻塞事件循环

### 7.2 Vue 前端（cloud-frontend）

- **Vue 版本**：3.x Composition API
- **组件命名**：PascalCase（如 `WardCard.vue`、`EventTrendChart.vue`）
- **API 调用**：统一在 `src/api/` 封装，组件不直接 fetch
- **中文文案**：界面文案中文，代码注释中文
- **样式**：Scoped CSS，配色统一用变量（蓝色科技风）

### 7.3 SQL（init.sql）

- **字符集**：`utf8mb4`
- **命名**：表名复数（wards / beds）、字段名 snake_case
- **注释**：每个字段加 `COMMENT`，每张表前用 `-- N. 表名` 分隔
- **索引**：高频查询字段建索引（idx_ward_state / idx_bed_time / idx_priority_state）
- **外键**：显式声明 FOREIGN KEY

### 7.4 MQTT 契约（contracts/）

- 任何 MQTT 主题或 payload 字段变更，**必须先改 contracts/ JSON Schema**
- Schema 变更需要更新 `schema_version`（当前 `v1`）
- 兼容性原则：新增字段向下兼容，删除/重命名字段需升 schema_version

### 7.5 文档（docs/）

- Markdown 格式，标题层级清晰（# / ## / ###）
- 表格用标准 Markdown 语法
- 代码块标注语言（```python / ```bash / ```sql）
- ASCII 图用等宽代码块包裹
- 引用项目内文件用相对路径（如 `edge-agent/src/fusion.py`）
- 禁止出现"TODO"、"待补充"、"占位"等未完成内容

### 7.6 Docker

- 镜像基于官方 slim/alpine 基础镜像
- 多阶段构建减小镜像体积
- `.dockerignore` 排除 `__pycache__/` / `node_modules/` / `.git/`
- 容器内非 root 用户运行（生产建议）

## 8. 提交频率与节奏

| 节点 | 提交频率 | 负责人 |
|------|---------|--------|
| 日常开发 | 每完成一个可验证功能即提交 | 全员 |
| 功能分支合并 | 测试通过后 24 小时内提 PR | 分支负责人 |
| master 发版 | 每周至少 1 次版本号递增 | 建鸿统筹 |
| 紧急修复 | 当天提交并合并 | 对应模块负责人 |

> 当前项目已发布至 v0.1.1（12 个 commit、约 8400 行代码与文档），后续按本规范持续推进，目标赛事交付前达到 v1.0.0 正式版。完整变更记录见 [CHANGELOG.md](../CHANGELOG.md)。

## 9. 禁止事项

- ❌ 直接向 `master` 分支 push
- ❌ 提交真实患者姓名/身份证/病历号等隐私数据
- ❌ 提交硬编码的数据库密码、MQTT 凭证（用环境变量）
- ❌ 提交大于 10MB 的二进制文件（模型文件用 LFS 或外部存储）
- ❌ 提交 `node_modules/` / `__pycache__/` / `.venv/` 等构建产物
- ❌ commit message 出现"TODO"、"临时"、"随便"等模糊描述
- ❌ 破坏 MQTT 契约向后兼容却未升 schema_version
- ❌ 删除已有单元测试以"让构建通过"
