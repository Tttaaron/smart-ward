# 架构设计文档

> 智慧病房云边协同系统 - 架构设计
> 本文档描述云边端三层总体架构、边缘代理架构、云端架构、技术选型、数据库设计、MQTT 主题规范、REST API 概览、WebSocket、Docker Compose 部署架构与安全设计。
> 复用智能教室项目技术路线，领域对象全部替换为病房安全监护。

> 当前实现状态：基础云边端架构和边缘侧 LLM 双路径已进入 v0.4.0；云端 LLM consumer、Qwen2.5-14B/vLLM 和 Jetson Orin Nano 实机验收仍未完成。本文的 Orange Pi/RKNN/YOLO 内容属于视觉与真实传感器接入方案，不能替代边缘语义 LLM 的实测结论。

## 2. 技术选型

### 2.1 边缘侧技术栈

| 组件 | 技术选型 | 理由 |
|------|----------|------|
| 开发语言 | Python 3.11 | 性能改进、类型注解完善、异步支持好 |
| MQTT 客户端 | paho-mqtt | 官方推荐，支持 QoS 1/2、断线重连 |
| 本地数据库 | SQLite | 轻量级，无需独立进程，适合边缘设备 |
| 边缘推理框架 | ONNX Runtime / OpenVINO / TensorRT | RK3588 NPU 加速，INT8 量化 |
| 视觉模型 | YOLO Nano 系（yolov8n/yolov10n/yolo11n） | 姿态 + 检测，INT8 量化后 < 100ms |
| 串口通信 | pyserial | ESP32 床垫传感器串口读取 |
| 容器化 | Docker | 统一环境，便于部署 |
| 日志 | logging | Python 标准库，无需额外依赖 |
| 硬件 | Orange Pi 5（RK3588 6TOPS NPU） | 算力充足、性价比高、NPU 加速 |
| 外设 | USB 摄像头 + ESP32 床垫传感器 | 通用易采购，覆盖主流感知 |

### 2.2 云端技术栈

| 组件 | 技术选型 | 理由 |
|------|----------|------|
| 后端框架 | FastAPI | 高性能，自动生成 API 文档，支持异步 |
| Web 服务器 | Uvicorn | ASGI 服务器，支持 WebSocket |
| 数据库 | MySQL 8.0 | 成熟稳定，支持事务与 JSON 字段 |
| ORM | SQLAlchemy 2.0 | 功能强大，支持多种数据库，异步友好 |
| 前端框架 | Vue 3 + Vite | 组件化开发，构建速度快 |
| 图表库 | ECharts | 功能强大，图表类型丰富 |
| 实时通信 | WebSocket | 双向通信，实时性好 |
| MQTT Broker | Mosquitto 2.0 | 轻量级，性能优秀 |
| 容器编排 | Docker Compose | 简单易用，适合 8 服务小规模部署 |
| 协同训练 | FastAPI + paho-mqtt | 与云端后端复用技术栈 |

### 2.3 契约与规范

| 组件 | 选型 | 说明 |
|------|------|------|
| MQTT 契约 | JSON Schema | `contracts/` 下 6 份 Schema，联调唯一标准 |
| 事件字典 | Markdown | `docs/00-事件字典.md`，事件层唯一标准 |
| MQTT 契约文档 | Markdown | `docs/01-MQTT契约.md`，接口层唯一标准 |
| 通用信封 | envelope.json | 7 字段：message_id/event_id/schema_version/occurred_at/source/trace_id/payload |
| 时间格式 | UTC ISO 8601 | `Z` 结尾，前端转本地时区显示 |
| 字段命名 | snake_case | 全栈统一 |

## 3. 数据库设计

### 3.1 边缘侧数据库（SQLite）

边缘 SQLite 缓存断网期间的事件与观测，恢复网络后按序补传：

#### 3.1.1 多源观测表（observations）

```sql
CREATE TABLE observations (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    ward_id VARCHAR(10) NOT NULL,
    node_id VARCHAR(30) NOT NULL,
    bed_id VARCHAR(10) NOT NULL,
    source_type VARCHAR(20) NOT NULL,  -- camera/bed_sensor/environment
    data TEXT NOT NULL,                 -- JSON 字符串
    quality TEXT,                       -- JSON 字符串
    timestamp DATETIME NOT NULL,
    synced BOOLEAN DEFAULT 0,
    INDEX idx_synced (synced),
    INDEX idx_timestamp (timestamp)
);
```

#### 3.1.2 安全事件表（safety_events）

```sql
CREATE TABLE safety_events (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    event_id VARCHAR(64) NOT NULL UNIQUE,
    ward_id VARCHAR(10) NOT NULL,
    node_id VARCHAR(30) NOT NULL,
    bed_id VARCHAR(10) NOT NULL,
    event_type VARCHAR(30) NOT NULL,
    priority VARCHAR(5) NOT NULL,
    state VARCHAR(20) NOT NULL DEFAULT 'new',
    confidence FLOAT NOT NULL,
    payload TEXT NOT NULL,              -- 完整事件 JSON
    occurred_at DATETIME NOT NULL,
    detected_at DATETIME,
    synced BOOLEAN DEFAULT 0,
    INDEX idx_synced (synced),
    INDEX idx_priority (priority)
);
```

#### 3.1.3 决策日志表（decision_log）

```sql
CREATE TABLE decision_log (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    node_id VARCHAR(30) NOT NULL,
    event_type VARCHAR(30) NOT NULL,
    rule_hits TEXT,                     -- JSON 命中规则列表
    confidence FLOAT,
    timestamp DATETIME NOT NULL,
    synced BOOLEAN DEFAULT 0
);
```

### 3.2 云端数据库（MySQL）

11 张表，完整覆盖病区/床位/节点/事件/告警/处置/模型/审计/交接班：

#### 3.2.1 病区表（wards）

```sql
CREATE TABLE wards (
    id VARCHAR(10) PRIMARY KEY,          -- 如 W-01
    name VARCHAR(50) NOT NULL,
    ward_type VARCHAR(20) DEFAULT 'general'
        COMMENT 'general/rehab/geriatric/maternity/pediatric',
    location VARCHAR(100),
    status VARCHAR(20) DEFAULT 'online',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

#### 3.2.2 床位表（beds）

```sql
CREATE TABLE beds (
    id VARCHAR(10) PRIMARY KEY,          -- 如 B01
    ward_id VARCHAR(10) NOT NULL,
    name VARCHAR(50) NOT NULL,
    patient_alias VARCHAR(50)
        COMMENT '演示用匿名别名，不存真实姓名',
    status VARCHAR(20) DEFAULT 'idle'
        COMMENT 'idle/occupied/alert/maintenance',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_ward (ward_id),
    FOREIGN KEY (ward_id) REFERENCES wards(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

#### 3.2.3 边缘节点表（edge_nodes）

```sql
CREATE TABLE edge_nodes (
    id VARCHAR(30) PRIMARY KEY,          -- 如 EDGE-W01-B01
    ward_id VARCHAR(10) NOT NULL,
    bed_id VARCHAR(10),
    status VARCHAR(20) DEFAULT 'offline'
        COMMENT 'online/degraded/offline',
    model_version VARCHAR(50),
    last_heartbeat DATETIME,
    buffered_events INT DEFAULT 0,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_ward (ward_id),
    INDEX idx_bed (bed_id),
    FOREIGN KEY (ward_id) REFERENCES wards(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

#### 3.2.4 观测数据表（observations）

```sql
CREATE TABLE observations (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    ward_id VARCHAR(10) NOT NULL,
    node_id VARCHAR(30) NOT NULL,
    bed_id VARCHAR(10) NOT NULL,
    source_type VARCHAR(20) NOT NULL
        COMMENT 'camera/bed_sensor/environment',
    data JSON NOT NULL,
    quality JSON,
    timestamp DATETIME NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_node_time (node_id, timestamp),
    INDEX idx_bed_time (bed_id, timestamp),
    INDEX idx_ward_type_time (ward_id, source_type, timestamp)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

#### 3.2.5 安全事件表（safety_events）【核心】

```sql
CREATE TABLE safety_events (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    event_id VARCHAR(64) NOT NULL UNIQUE,   -- 边缘端 UUID4，全局唯一
    ward_id VARCHAR(10) NOT NULL,
    node_id VARCHAR(30) NOT NULL,
    bed_id VARCHAR(10) NOT NULL,
    event_type VARCHAR(30) NOT NULL,
    priority VARCHAR(5) NOT NULL COMMENT 'P1/P2/P3',
    state VARCHAR(20) NOT NULL DEFAULT 'new'
        COMMENT 'new/notified/acknowledged/resolved/false_positive/escalated',
    confidence FLOAT NOT NULL,
    model_name VARCHAR(50) NOT NULL,
    model_version VARCHAR(50) NOT NULL,
    inference_ms INT DEFAULT 0,
    evidence_refs JSON,
    rule_hits JSON,
    details JSON,
    occurred_at DATETIME NOT NULL,
    detected_at DATETIME,
    acknowledged_at DATETIME,
    resolved_at DATETIME,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_ward_state (ward_id, state),
    INDEX idx_bed_time (bed_id, occurred_at),
    INDEX idx_priority_state (priority, state),
    INDEX idx_event_type (event_type)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

#### 3.2.6 告警任务表（alert_tasks）

```sql
CREATE TABLE alert_tasks (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    event_id VARCHAR(64) NOT NULL,
    ward_id VARCHAR(10) NOT NULL,
    bed_id VARCHAR(10) NOT NULL,
    priority VARCHAR(5) NOT NULL,
    channel VARCHAR(20) DEFAULT 'ws' COMMENT 'ws/sms/email',
    notified_at DATETIME,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_event (event_id),
    INDEX idx_ward_priority (ward_id, priority),
    FOREIGN KEY (event_id) REFERENCES safety_events(event_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

#### 3.2.7 事件处置表（event_dispositions）

```sql
CREATE TABLE event_dispositions (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    event_id VARCHAR(64) NOT NULL,
    action VARCHAR(20) NOT NULL
        COMMENT 'acknowledge/resolve/false_positive/escalate',
    operator_id VARCHAR(50) NOT NULL,
    operator_name VARCHAR(50),
    operator_role VARCHAR(20),            -- nurse/charge_nurse/admin/observer
    result VARCHAR(200),
```

### 3.3 事件状态机

```
                ┌─────────────┐
                │     new     │  边缘端新生成
                └──────┬──────┘
                       │ 云端收到并入库
                       ▼
                ┌─────────────┐
                │   notified  │  已推送到护士站
                └──────┬──────┘
                       │ 护士点击"到场"
                       ▼
                ┌─────────────┐
     ┌──────────│ acknowledged│  已确认（开始处置）
     │           └──────┬──────┘
     │                  │
     │     ┌────────────┼────────────┐
     │     ▼            ▼            ▼
     │ ┌───────┐  ┌──────────┐  ┌───────────┐
     │ │resolved│  │false_    │  │escalated  │
     │ │       │  │positive  │  │           │
     │ │已处置 │  │误报      │  │升级       │
     │ └───────┘  └──────────┘  └───────────┘
     │
     └─ 从 acknowledged 也可直接 resolve/false_positive/escalate
```

**状态转换规则**：

| 当前态 | 允许的 action | 目标态 |
|---|---|---|
| `new` | （云端自动） | `notified` |
| `notified` | acknowledge | `acknowledged` |
| `notified` | resolve | `resolved` |
| `notified` | false_positive | `false_positive` |
| `notified` | escalate | `escalated` |
| `acknowledged` | resolve | `resolved` |
| `acknowledged` | false_positive | `false_positive` |
| `acknowledged` | escalate | `escalated` |
| `resolved` / `false_positive` / `escalated` | （终态） | - |

## 6. 安全设计

### 6.1 MQTT 安全

- **当前演示阶段**：`allow_anonymous true`，仅用于演示
- **接入真实病房前必须启用**：
  - 账号密码认证（每节点独立账号）
  - ACL 主题权限（限制每个节点只能发布自己的主题 `ward/{ward_id}/node/{node_id}/*`）
  - TLS 加密（MQTT over SSL，端口 8883）
- QoS=1 保证消息至少一次送达，消费端按 `message_id` 幂等去重
- `retained: false`，不使用保留消息（health 用周期心跳替代）

### 6.2 API 安全

- 输入参数校验（Pydantic Schema）
- HTTPException 统一错误处理
- 演示阶段无认证，接入真实病房需启用 JWT Token 认证
- API 限流防止滥用（建议 nginx 层实现）

### 6.3 数据安全

- **隐私脱敏**：默认仅上传事件摘要、脱敏截图或裁剪片段指针；原始视频留边缘端
- **匿名别名**：患者信息使用演示别名（如"演示患者-001"），不存真实姓名
- **误报回流**：`false_positive` 标记作为训练数据回流前必须脱敏与人工审核
- **审计留痕**：所有事件创建/确认/处置/模型下发操作进入 `audit_logs` 表
- MySQL 数据定期备份（`mysql-data` volume）
- 日志脱敏处理（不记录患者真实信息）

### 6.4 边缘安全

- 模型加载失败自动回退到上一版本
- MQTT 客户端断线自动重连（指数退避）
- SQLite 缓存上限保护（最多 10000 条，FIFO 淘汰）
- 推理超时保护（单帧 > 500ms 告警）

## 7. 监控和日志

### 7.1 日志级别

- DEBUG: 详细调试信息（采集原始数据、规则命中详情）
- INFO: 正常运行信息（事件生成、状态流转、模型下发）
- WARNING: 警告信息（节点降级、推理超时、缓存接近上限）
- ERROR: 错误信息（MQTT 断连、数据库写入失败、模型加载失败）

### 7.2 日志内容

- 多源采集日志（每路 source_type 的 quality.degraded 状态）
- 融合决策日志（rule_hits 命中、confidence 计算）
- MQTT 连接状态日志（连接/断开/重连）
- 事件生成与状态流转日志
- 模型下发与加载日志
- API 请求日志
- WebSocket 连接日志
- 错误异常日志（含堆栈）

### 7.3 监控指标

- 节点在线状态（online/degraded/offline）
- 节点健康心跳（每 30 秒一次，超时 90 秒判定失联）
- 缓冲事件数（buffered_events，反映断网时长）
- 消息发送成功率
- API 响应时间
- 数据库连接数
- 推理耗时分布（inference_ms）
- 事件总数 / P1/P2/P3 分布
- 事件处置闭环时长（occurred_at -> resolved_at）
- 模型版本分布与灰度进度
