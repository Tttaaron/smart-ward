# 需求分析文档

> 智慧病房云边协同系统 - 需求分析
> 本文档描述病房场景下的核心痛点、解决方案、功能需求与非功能需求。
> 复用智能教室云边协同节能系统技术路线，领域对象全部替换为病房安全监护。

## 1. 项目背景

### 1.1 问题描述

现代医院病房护理面临"三不过来"的核心痛点，护士人手长期不足与患者护理风险点高发之间的矛盾日益突出：

- **看不过来**：一名护士通常需同时看护 8-12 张床位，夜间值班人力更少；摄像头、床垫、输液、环境多源信息分散在不同屏幕，护士难以同时关注所有床位的安全状态。
- **跑不过来**：跌倒、坠床、抽搐、夜间徘徊等高风险事件往往发生在一瞬间，等护士听到动静赶到时往往已造成伤害；夜间跨病区巡查存在 3-5 分钟的盲区。
- **记不过来**：当前交接班、巡视记录、输液进度、压疮翻身提醒等大量依赖纸质记录与人工记忆，信息滞后且易遗漏；高危患者的体位变化、长时间静止等早期信号几乎无人记录。

具体病房护理风险场景：

- 跌倒：术后/老年患者起身如厕时跌倒，是医院排名前三的不良事件
- 坠床：儿科/老年/意识不清患者翻身坠床，夜间高发
- 离床：术后患者擅自下床活动，可能引发跌倒或伤口撕裂
- 输液异常：输液完成未及时换瓶、滴速异常、管路脱落或堵塞
- 夜间徘徊：老年痴呆/谵妄患者夜间游走，存在跌倒、走失风险
- 压疮：长期卧床患者同一体位持续超过 2 小时未翻身，易产生压疮
- 抽搐：癫痫患者夜间发作未被发现
- 环境异常：病房温度异常、CO₂ 超标影响患者康复
- 设备故障：传感器失灵、摄像头遮挡导致监护盲区
- 节点失联：边缘设备断网、断电造成整段病区监护空窗

现有病房监护系统的局限：

- 呼叫按钮需患者主动触发，失能/昏迷/跌倒患者无法使用
- 中央监护屏只能看视频，无法自动识别风险
- 一次性设备多，数据孤岛严重，缺乏跨床位/跨病区联动
- 完全依赖云端，断网即失能，无法满足病房 7×24 小时不间断监护要求

### 1.2 解决方案

基于云边协同的智慧病房安全监护系统，实现：

- **边缘自主决策**：每个床位配备独立边缘代理（Orange Pi 5 + RK3588 NPU），本地融合摄像头、床垫传感器、输液监测、环境数据，断网情况下仍可独立识别风险并本地告警
- **云端集中监控**：护士站大屏实时展示全病区床位状态、安全事件、告警工作台，支持确认/处置/升级闭环
- **断网可用**：边缘节点断网后 SQLite 本地缓存事件，恢复网络后按序补传，期间本地仍持续告警
- **隐私脱敏**：默认仅上传事件摘要与脱敏截图/片段指针，原始视频留边缘端，符合病房隐私合规要求
- **模型协同**：云端扩散模型生成困难样本，分布式训练（FedAvg）聚合多节点模型，灰度下发新版本到边缘端

### 1.3 项目定位

本项目从智能教室云边协同节能系统复用技术路线（云边端三层架构、Docker Compose 编排、MQTT 通信、FastAPI + Vue3 + MySQL 技术栈、断网自治能力），领域对象替换为病房安全监护：

| 维度 | 智能教室项目 | 智慧病房项目 |
|------|-------------|-------------|
| 场景 | 教室节能 | 病房安全监护 |
| 监控对象 | 教室 | 病床 |
| 决策目标 | 节能（关灯/空调） | 安全告警 + 闭环处置 |
| 事件类型 | 设备状态变化 | 14 类安全事件 |
| 决策模式 | 自动控制设备 | 辅助提示 + 人工复核 |
| 隐私要求 | 一般 | 高（患者隐私脱敏） |
| 实时性要求 | <2 秒 | <2 秒（P1 紧急） |

## 2. 功能需求

### 2.1 边缘侧功能

#### 2.1.1 多源数据采集

4 类采集适配器，覆盖病房主流感知设备：

- **CameraAdapter（AI 摄像头）**：每 3 秒采集一帧，输出人员存在、人数、体态（sitting/lying/standing/falling/lying_edge/curled/leaning/grabbing_chest）、跌倒置信度 fall_score
- **BedSensorAdapter（ESP32 床垫传感器）**：每 3 秒采集一次，输出床位占用状态、bed_state（occupied/empty/absence_seconds）、体动信号
- **InfusionAdapter（输液监测）**：每 5 秒采集一次，输出滴速、剩余液量、输液状态（normal/complete/blocked/anomaly）
- **EnvironmentAdapter（环境传感器）**：每 10 秒采集一次，输出温度、湿度、CO₂、光照

每路观测数据携带 `source_type` 与 `quality`（confidence/latency_ms/degraded）三字段，供融合引擎做置信度加权。

#### 2.1.2 融合引擎与规则决策

融合引擎 `fusion.py` 综合多源观测，按事件类型触发对应规则。决策规则示例：

```
决策规则（节选）：

1. fall_suspected（疑似跌倒）P1
   - 摄像头 posture = falling AND fall_score > 0.5 AND 床位 absence_seconds > 0
   - 边缘端立即本地告警，不等待云端响应

2. fall_prediction（坠床预警）P1
   - 床位 occupied = true AND posture = lying_edge AND fall_score 超阈值
   - 事前预警，比跌倒更早触发

3. bed_leave（离床）P2
   - 床位 absence_seconds >= 30s（阈值可配置）
   - 术后/老年患者需更短阈值

4. long_still（长时间静止）P2
   - 同一体位持续 >= 5 分钟（阈值可配置）
   - 可能是昏迷/不适，需护士关注

5. seizure（抽搐检测）P1
   - tremor_score 超阈值
   - 可能是癫痫发作

6. bedsore_risk（压疮预防）P3
   - 同一体位持续 >= 2 小时
   - 提醒护士协助翻身

7. environment_anomaly（环境异常）P3
   - 温度/CO₂/光照超阈值

8. device_fault（设备故障）P3
   - 传感器 quality.degraded 持续 >= 60 秒

9. node_offline（节点失联）P3
   - 云端检测：边缘节点健康心跳超时
```

14 类事件类型完整清单见 §2.2.2。

#### 2.1.3 离线缓存与断网自治

- 断网时本地 SQLite 存储事件，标记 `synced=0`
- 恢复网络后按 `message_id` 顺序补传，标记 `synced=1`
- 断网期间本地仍持续告警（P1 事件本地置顶闪烁）
- `event_id` 全局唯一，云端按此去重，断网补传不产生重复告警

#### 2.1.4 数据上报

- 观测数据每 3 秒上报一次（按 `TICK_SECONDS` 配置）
- 安全事件实时上报（发生即上报）
- 节点健康心跳每 30 秒上报一次
- 使用 MQTT 协议，QoS=1，按 `message_id` 幂等去重
- 通用消息信封 7 字段：`message_id`/`event_id`/`schema_version`/`occurred_at`/`source`/`trace_id`/`payload`

#### 2.1.5 模型下发与灰度

- 接收云端 `model/deploy` 主题，加载新模型版本
- 支持灰度发布（按节点）、回滚（`model/rollback`）
- 模型加载失败自动回退到上一版本并上报

### 2.2 云端功能

#### 2.2.1 护士站实时大屏

- **顶栏统计**：在线节点数、待处理 P1/P2 事件数、当前班次
- **床位卡片**（每病区多床位）
  - 床位编号（B01/B02/B03）
  - 患者别名（演示用匿名别名，不存真实姓名）
  - 当前体态（sitting/lying/standing，图标）
  - 床位状态（idle/occupied/alert/maintenance）
  - 摄像头/床垫/输液/环境多源状态指示灯
  - 最后更新时间
- **告警工作台**
  - P1 紧急事件置顶闪烁，要求护士立即确认
  - P2 高优先级进入待办队列，5 分钟内确认
  - P3 提醒事件可批量处理
  - 支持"到场 acknowledge / 处置 resolve / 误报 false_positive / 升级 escalate"四个动作
- **数据可视化**
  - 事件趋势图（最近 24 小时按事件类型/优先级）
  - 节点延迟看板（推理耗时、上报延迟）
  - 模型性能看板（版本、置信度分布、误报率）

#### 2.2.2 14 类安全事件

| event_type | 中文名 | 优先级 | 默认来源 | 说明 |
|---|---|---|---|---|
| `fall_suspected` | 疑似跌倒 | P1 | 边缘端 | 摄像头姿态=falling + fall_score>0.5 + 床位离床 |
| `nurse_call` | 护士呼叫 | P1 | 前端/按钮 | 护士呼叫按钮触发，边缘端可透传 |
| `bed_leave` | 离床 | P2 | 边缘端 | 床位 absence_seconds >= 阈值（默认 30s） |
| `infusion_anomaly` | 输液异常 | P2 | 边缘端 | 滴速异常/低液位/输液完成/中断 |
| `door_departure` | 门区异常离开 | P2 | 边缘端 | 门磁 open + 摄像头检测到人离开区域 |
| `night_wandering` | 夜间徘徊 | P2 | 边缘端 | 夜间时段（22:00-06:00）+ 持续离床 |
| `environment_anomaly` | 环境异常 | P3 | 边缘端 | 温度/CO₂/光照超阈值 |
| `node_offline` | 节点失联 | P3 | 云端 | 边缘节点健康心跳超时 |
| `fall_prediction` | 坠床预警 | P1 | 边缘端 | 床位占床 + 姿态=lying_edge + fall_score 超阈值 |
| `long_still` | 长时间静止 | P2 | 边缘端 | 同一体位持续超阈值（默认 5 分钟） |
| `abnormal_posture` | 异常体态 | P2 | 边缘端 | posture 命中 curled/leaning/grabbing_chest |
| `seizure` | 抽搐检测 | P1 | 边缘端 | tremor_score 超阈值 |
| `bedsore_risk` | 压疮预防 | P3 | 边缘端 | 同一体位持续超阈值（默认 2 小时） |
| `device_fault` | 设备故障 | P3 | 边缘端 | 传感器 quality.degraded 持续超阈值（默认 60 秒） |

#### 2.2.3 10 项智能功能

1. **坠床预警（fall_prediction）**：基于床位占用 + 体态边缘 + 跌倒置信度，提前于跌倒触发告警
2. **跌倒检测（fall_suspected）**：摄像头姿态 falling + fall_score 阈值融合判定
3. **长时间静止（long_still）**：同一体位持续监测，可能是昏迷/不适
4. **异常体态（abnormal_posture）**：curled/leaning/grabbing_chest 可能是急症早期信号
5. **抽搐检测（seizure）**：tremor_score 阈值判定，可能是癫痫发作
6. **压疮预防（bedsore_risk）**：2 小时未翻身提醒
7. **交接班摘要（shift_summaries）**：自动汇总班次事件，护士确认后归档
8. **环境自适应（environment_anomaly）**：温度/CO₂/光照超阈值联动告警
9. **空气质量联动（env/control）**：云端下发指令控制空调/灯光/新风
10. **床位可视化（beds/occupancy）**：全病区床位占用状态一览，支持 3D 视图
11. **设备故障（device_fault）**：传感器降级持续超阈值告警

#### 2.2.4 交接班闭环

- **班次周期**：day（白班 08:00-16:00）/ evening（晚班 16:00-24:00）/ night（夜班 00:00-08:00）
- **自动汇总**：系统按班次自动汇总该病区事件总数、P1/P2/P3 计数、未处理事件、需关注患者
- **护士确认**：交接班时由接班护士确认摘要，签字归档
- **历史查询**：支持按病区/班次/日期查询历史交接班记录

#### 2.2.5 环境联动控制

- 云端手动控制空调/灯光/新风（ac/light/fresh_air on/off）
- 控制指令通过 MQTT `node/{node_id}/config/set` 下发
- 手动控制 5 分钟后自动恢复自动模式
- 与 environment_anomaly 事件联动：温度过高自动开空调、CO₂ 超标自动开新风

#### 2.2.6 模型管理

- 模型版本管理（draft/validating/released/deprecated/rolled_back）
- 灰度发布：按节点逐步下发新模型版本
- 回滚：一键回滚到上一稳定版本
- 性能看板：召回率、误报率、推理耗时、置信度分布

#### 2.2.7 系统管理

- 病区管理（添加/编辑/删除）
- 床位管理（绑定边缘节点、患者别名）
- 节点管理（在线状态、缓冲事件数、模型版本）
- 审计日志（事件创建/确认/处置/模型下发全留痕）

## 3. 非功能需求

### 3.1 性能要求

- **告警时延**：从边缘端事件发生到护士站大屏显示 ≤ 2 秒（P1 紧急事件）
- **观测数据上报延迟**：边缘发送到云端接收 < 1 秒
- **大屏刷新频率**：≥ 1 次/秒
- **推理耗时**：单帧 ≤ 100 毫秒（Orange Pi 5 RK3588 NPU，INT8 量化）
- **断网补传吞吐**：≥ 100 条/秒
- **支持并发**：3 个边缘节点同时运行（演示规模），可扩展到 12+ 床位

### 3.2 可靠性要求

- 边缘节点断网后仍可正常决策与本地告警（P1 事件本地置顶）
- 数据缓存不丢失（SQLite 持久化，事件按 `message_id` 幂等）
- 系统 7×24 小时稳定运行
- 模型加载失败自动回退到上一版本
- MQTT 客户端断线自动重连

### 3.3 可用性要求

- Web 界面响应式设计，支持 1920×1080 护士站大屏
- 操作简单，护士无需培训即可使用（点击确认/处置/误报/升级四个动作）
- P1 事件视觉强提示（红色闪烁 + 声音提醒）
- 提供操作日志、错误提示、错误恢复指引

### 3.4 可维护性要求

- 代码结构清晰，注释完整（edge-agent / cloud-backend / cloud-frontend / training-coordinator 分层）
- 提供完整的部署文档（Docker Compose 一键启动）
- 契约驱动开发（`contracts/` 下 JSON Schema 是联调唯一标准）
- 支持灰度发布与回滚

### 3.5 实时性要求

- P1 事件：从发生到护士站显示 ≤ 2 秒，要求护士立即确认
- P2 事件：5 分钟内确认
- P3 事件：进入待办队列，可批量处理
- 节点健康心跳：每 30 秒一次，超时 90 秒判定失联

### 3.6 隐私与合规要求

- **隐私脱敏**：默认仅上传事件摘要、脱敏截图或裁剪片段指针；原始视频留边缘端
- **匿名别名**：患者信息使用演示别名（如"演示患者-001"），不存真实姓名
- **误报回流**：`false_positive` 标记作为训练数据回流前必须脱敏与人工审核
- **审计留痕**：所有事件创建/确认/处置/模型下发操作进入 audit_logs

### 3.7 可演示性要求

- 一键启动（`docker compose up --build`）
- 8 服务 Docker Compose 编排（mqtt-broker/mysql/cloud-backend/training-coordinator/cloud-frontend/edge-bed-01/02/03）
- 场景注入台：支持手动注入任意 14 类事件触发场景
- 3 床 6 场景演示编排：
  - B01：fall + nurse_call + fall_prediction + seizure
  - B02：bed_leave + night_wandering + long_still + bedsore_risk
  - B03：environment_anomaly + door_departure + abnormal_posture + device_fault

## 7. 病房画像

不同病房类型对系统的需求侧重不同，系统支持按 `ward_type` 差异化配置：

| ward_type | 中文名 | 高发事件 | 阈值侧重 | 特殊需求 |
|---|---|---|---|---|
| `general` | 普通病房 | bed_leave、infusion_anomaly、nurse_call | 默认阈值 | 通用监护 |
| `rehab` | 康复病房 | fall_suspected、fall_prediction、long_still | 离床阈值收紧（20s） | 术后患者防跌倒 |
| `geriatric` | 老年病房 | fall_suspected、night_wandering、bedsore_risk、abnormal_posture | 静止/翻身阈值收紧 | 谵妄/痴呆防走失 |
| `maternity` | 妇产病房 | nurse_call、infusion_anomaly | 默认阈值 | 隐私加强 |
| `pediatric` | 儿科病房 | fall_suspected、bed_leave、abnormal_posture | 离床阈值收紧（15s） | 坠床高发 |

## 8. 边界约束

明确系统**不做**的事情，避免范围蔓延与责任误读：

### 8.1 不做诊断

- 系统仅输出"疑似事件/辅助提示"，不提供医学诊断结论
- `fall_suspected` 表示"疑似跌倒"，是否真跌倒由护士到场判断
- `abnormal_posture` 表示"异常体态"，可能是急症早期信号，具体病情由医生诊断
- `seizure` 表示"抽搐检测"，是否癫痫发作由医生判断

### 8.2 不做自动控制

- 系统不自动执行任何临床处置（不给药、不操作医疗设备）
- 环境控制仅限空调/灯光/新风等非医疗设备
- 所有事件处置必须由护士主动确认（acknowledge/resolve/false_positive/escalate）

### 8.3 不替代医护

- 系统是辅助提示工具，不替代护士巡视与专业判断
- 护士仍需按医院规定完成巡视、交接班等本职工作
- 系统告警不能作为医疗事故责任划分的唯一依据
- 护士对事件的最终处置结果负责

### 8.4 不存敏感数据

- 不存储患者真实姓名、身份证号、病历号
- 演示阶段使用匿名别名（如"演示患者-001"）
- 原始视频留边缘端，仅上传脱敏截图/片段指针
- `false_positive` 误报回流训练前必须脱敏与人工审核
